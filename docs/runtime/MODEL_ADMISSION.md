# 单模型准入与硬件基线

- 状态：当前产品基线
- 日期：2026-09-14
- 适用范围：Ollama 与 OpenAI 兼容模型连接

## 产品约束

Vinkey 只启用一个功能模型。分析、续写、改稿和审校等场景由 Skill 调整提示词、上下文与工作流，不维护轻量模型、综合模型等角色分配，也不允许在对话输入区临时切换模型。

模型连接可以发现多个候选模型。用户新选择的活动模型必须先通过检查；已有活动模型缺少有效检查结果时仍会保留，并提示重新检查。连接和模型配置保存在本机数据库；唯一活动模型 ID 保存在本地应用存储。

## 准入要求

自动准入门槛包括：

1. 连接可用，能够从 Ollama `/api/tags` 或 OpenAI 兼容 `/models` 获取目录。
2. Ollama 接口接受 `format` Schema，或 OpenAI 兼容接口接受 `response_format: json_schema`。
3. 返回内容能解析为 JSON，并符合探测 Schema 约定的字段和值。

当前自动检查不评测中文创作质量，也不保证模型的理论最大上下文窗口。对 Ollama，检查会读取模型元数据，并在上下文超限时自动降低请求值后重试，最终保存模型实际接受的安全值；其他兼容服务使用 8,192 tokens 的保守值。中文质量和更大上下文容量属于独立的产品测试与运行时验证。

模型列表、检查结果和自动配置的上下文长度会按连接 ID、接口协议与 Base URL 缓存。服务参数变化后缓存失效，用户可以手动刷新列表或重新检查。API Key 不进入浏览器缓存。

## 硬件档位

| 档位 | Apple Silicon 统一内存 | 独立显卡设备（内存 / 单卡显存） |
| --- | --- | --- |
| 最低配置 | 16 GB | 16 GB / 8 GB |
| 标准配置 | 32 GB | 32 GB / 16 GB |
| 推荐配置 | 64 GB | 64 GB / 24 GB |

硬件档位只描述本地运行容量，不自动指定模型，也不属于模型检查结果。本机 Ollama 检查从 16,384 tokens 开始；长文本任务继续使用分块和 Map/Reduce/Synthesis，不要求一次载入整部作品。

## 模型生命周期

模型检查会逐一测试候选模型，并在每个本机 Ollama 模型检查结束后发送 `keep_alive: 0`，避免多个模型同时驻留而污染显存测量。

正常业务请求始终使用唯一活动模型。应用不提供“自动释放旧模型”或“停止驻留模型”设置，也不公开模型停止命令；业务模型的驻留周期由 Ollama 或远程服务管理。

## 旧设计清理

旧的模型角色分配、聊天区模型覆盖、自动停止偏好和手动停止命令均不再属于产品合同。启动时会删除历史 `vinkey.modelAssignments` 与 `vinkey.autoStopOllamaModels` 本地配置。
