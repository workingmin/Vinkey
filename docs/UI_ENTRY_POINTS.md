## 文档职责

本文件是跨页面业务功能入口的唯一设计索引，回答“用户从哪里开始一项业务操作、需要什么前置条件、操作后到哪里”。它不替代页面设计文档：

- `UI_INVENTORY.md` 记录当前已有的页面和交互事实。
- `UI_ENTRY_POINTS.md` 记录跨页面入口、入口文案、前置条件、目标页面和实现状态。
- `UI_DESIGN_*.md` 记录对应页面或交互域的布局、详细步骤、状态、隐私边界和验收标准。
- `UI_DESIGN.md` 只维护信息架构、跨域原则和文档索引。

入口状态统一使用：`已实现`、`部分实现`、`待实现`。同一个入口在不同平台行为不同的，必须在实现状态中说明平台差异。

## 入口模型

每项业务入口至少描述以下字段：

| 字段 | 说明 |
| --- | --- |
| 功能 | 用户要完成的业务目标，不写成组件名称 |
| 入口位置 | 标题栏、侧栏、内容区、消息或上下文操作 |
| 入口文案 | 用户实际看到的菜单、按钮或标签文本 |
| 前置条件 | 工作区、会话、文档、模型或任务状态要求；没有前置条件写“无” |
| 目标 | 进入的页面、面板、对话预填状态或任务状态 |
| 状态保持 | 说明是否保持当前工作区、会话、编辑内容和上下文 |
| 实现状态 | 已实现、部分实现或待实现 |
| 详细设计 | 链接到负责该入口的域文档 |

入口命名使用业务语言，不使用 `TaskCenter`、`dispatch` 等内部实现名；图标按钮必须同时由对应域文档定义 tooltip 和无障碍名称。

## 入口行为规则

1. 入口只改变完成业务目标所需的页面或状态，不隐式改变当前工作区、会话、文档内容或模型选择。
2. 跨工作区操作必须以当前 `workspaceId` 为边界；异步返回晚于工作区切换时不得覆盖新工作区 UI。
3. 需要模型、文档或任务状态的入口必须在不可用时显示原因，并提供可达的替代入口或返回路径。
4. 进入设置、切换工作区和删除记录前，必须按对应域文档检查运行任务、未保存修改和确认条件。
5. 入口文案、快捷键、菜单命令和无障碍名称在 Windows、macOS 保持同一业务语义；平台差异只体现在承载控件。
6. 每个入口必须有键盘路径；图标按钮提供 `title` 和 `aria-label`，状态不能只依赖颜色。
7. 入口触发的错误应留在触发上下文中；跨域错误才提升为全局错误反馈。

## 维护规则

- 新增业务功能时，先在本文件增加入口记录，再更新对应域设计文档和 `UI_INVENTORY.md`。
- 入口位置或文案变化时，同时检查标题栏、侧栏、内容区、快捷键和 macOS 原生菜单。
- 入口实现状态变化时，只更新本文件和现状盘点；详细设计中的流程状态必须同步更新。
- 不在本文件重复色彩、间距、组件尺寸等视觉 token；统一引用 `UI_DESIGN_SYSTEM.md`。
- 目标态入口必须写出前置条件、失败处理和数据/隐私边界，不能只列一个按钮名称。

## 入口验收

1. 用户能从入口表中找到每项首版业务功能的唯一主入口和可用替代入口。
2. 每个入口的前置条件、目标页面和状态保持描述与当前实现一致。
3. Windows、macOS 菜单和页面标签对同一功能使用一致的业务语义。
4. 无工作区、无模型、无文档、任务运行中和未保存等前置条件不足时，入口不会静默失败或丢失用户状态。
5. 跨页面入口不会把任务、会话、工作区和文档内容混淆；异步操作不会回写已切换的工作区。
6. 所有入口都有键盘可达路径、明确的焦点状态和可读的图标辅助文本。
