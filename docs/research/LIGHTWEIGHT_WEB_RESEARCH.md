# Vinkey 轻量级联网搜索设计

- 状态：下一版本候选方案
- 日期：2026-09-07
- 产品定位：本地 AI 文学创作工作台中的显式、受控、可信来源检索

## 1. 决策结论

Vinkey 可以在不接入商用付费搜索供应商、不建设外部网页正文库的前提下，增加轻量级联网搜索。该能力对事实核查、历史与地域考据、职业和专业细节、开放文献查找的收益高；对续写、润色、文风保持等核心文本生成任务的直接收益低。

综合产品收益评为 **中等（3/5）**，研究型创作场景评为 **高（4.5/5）**。这些分值是产品假设，不是已经验证的用户指标。联网搜索不应替代项目记忆、连续性审校、人物关系和改稿链路，也不应成为普通创作请求的默认前置步骤。

建议作为下一版本的可选功能推进，名称采用“可信资料检索”或“联网考据”，默认关闭，只有用户主动点击后才访问网络。首期先完成来源地址列表管理和有限来源的实时检索闭环，再用基准任务决定是否继续扩充来源和爬虫能力。

## 2. 功能收益评估

| 创作任务 | 收益 | 主要价值 | 主要限制 |
| --- | --- | --- | --- |
| 历史、地域、制度和文化考据 | 很高 | 降低时代、地点和制度常识错误 | 可信来源覆盖不完整，不同来源可能冲突 |
| 职业、科技、医学等专业细节 | 高 | 为场景和行为细节提供事实参照 | 免费来源常只有概述，不能替代专业审校 |
| 人物、事件、文物和典籍出处 | 高 | 提供原始链接、机构和访问时间 | 需要跨语言名称归一和来源去重 |
| 用户选中文本后的事实核查 | 很高 | 将模型固有知识改为可核验外部证据 | 检索词可能泄露选中文本含义，必须预览 |
| 世界观和情节灵感 | 中等 | 提供现实素材和组合方向 | 容易引入无关信息或削弱作品原创性 |
| 书名、简介和投稿资料 | 中等 | 可查机构规则、公开资料和同类信息 | 时效性和完整性受来源列表约束 |
| 续写、扩写和场景生成 | 低 | 仅在场景依赖现实知识时有帮助 | 决定质量的仍是原文上下文和创作模型 |
| 润色、节奏和文风保持 | 很低 | 通常没有必要联网 | 外部资料会增加噪声、延迟和上下文占用 |
| 项目连续性、人物关系和伏笔检查 | 很低 | 外网不能证明作品内部事实 | 应继续使用本地正文证据和项目记忆 |

该模块的核心收益不是普遍提升模型文笔，而是把部分“凭模型记忆回答”转换为“基于当前外部证据回答”。它主要降低事实幻觉，并减少用户在浏览器和 Vinkey 之间切换、整理链接和复制资料的成本。

## 3. 明确范围

### 3.1 本期包含

1. 冷启动来源地址列表。
2. 用户主动触发的“一键更新来源”：发现候选来源、验证地址、新增合格来源、停用持续失效来源。
3. 用户新增、编辑、启用、停用、删除、恢复、导入和导出来源配置。
4. 基于来源列表的实时搜索：调用来源原生 API、站内搜索、RSS、Sitemap 或有限 HTML 页面。
5. 临时抓取少量命中页面，提取与当前问题相关的证据片段并交给模型。
6. 来源引用、访问时间、搜索覆盖和失败原因展示。

### 3.2 本期不包含

- 商用付费搜索 API 或由 Vinkey 运营的搜索代理服务。
- 自动计划任务；“至少每日一次”是免费接口容量目标，不表示应用每天自动运行。
- 下载并持久保存外部网站正文。
- 为外部网页建设 SQLite FTS、向量库或其他本地全文索引。
- 对站点进行全量、递归或持续爬取。
- 登录态网站、付费墙、验证码或反爬机制绕过。
- 导入系统浏览器 Cookie、模拟真实用户规避访问限制。
- 让模型自动编写并执行爬虫代码。
- 将联网证据自动写入项目记忆、世界书或用户文稿。

来源地址列表更新、用户实时搜索和外部正文索引是三个独立能力。本方案只实现前两个；更新来源时允许临时读取首页标题、API 描述、`robots.txt`、RSS 和 Sitemap 等验证信息，任务结束后丢弃，不保存网页正文。

## 4. 来源地址列表

来源列表不是 URL 字符串集合，而是描述“去哪里查、怎样查、当前是否可用”的来源注册表。

```ts
interface ResearchSource {
  id: string
  name: string
  origin: 'builtin' | 'catalog' | 'discovered' | 'user'
  adapter: 'mediawiki' | 'json-api' | 'rss' | 'sitemap' | 'opds' | 'html-search' | 'fetch-only'
  baseUrl: string
  allowedHosts: string[]
  searchEndpoint?: string
  language: string[]
  region: string[]
  categories: string[]
  trustLevel: 'official' | 'curated' | 'community' | 'custom'
  status: 'candidate' | 'active' | 'restricted' | 'unavailable' | 'retired'
  userEnabled: boolean
  minimumUpdateHours: number
  lastCheckedAt?: number
  lastSuccessAt?: number
  consecutiveFailures: number
}
```

没有搜索 API、Feed、Sitemap 或站内搜索配置的地址必须标记为 `fetch-only`。它只能读取用户提供的具体页面，不能宣称具备站内搜索能力。

最终配置按以下优先级合并：

```text
内置冷启动目录
  + 已验证的来源目录更新
  + 用户本地新增和覆盖
  - 用户本地停用和隐藏
```

目录更新不能覆盖用户修改，不能重新启用用户主动关闭的来源。来源停用采用软删除并保留历史，避免临时网络故障导致不可恢复的数据变化。

## 5. 一键更新来源

“一键更新”由用户主动触发，每个滚动 24 小时至少应有一次完整免费执行额度。一次完整更新可以包含多个 HTTP 请求，因此选择免费接口时必须按一次更新任务的总请求预算评估，不能只确认接口每天赠送一次请求。

```text
用户点击更新
  -> 读取免费额度、冷却时间和上次检查游标
  -> 获取签名来源目录并调用允许的免费发现接口
  -> Rust 确定性解析 API JSON
  -> 本地模型对候选机构分类、去重和相关性排序
  -> 检测候选 URL、搜索入口、许可和访问状态
  -> 分批复检已有来源
  -> 生成新增、修改、限制、停用差异
  -> 用户确认或按明确规则应用
  -> 只保存来源元数据、健康状态和变更历史
```

建议一次更新最多执行 3 至 5 个发现查询、接收 10 至 20 个候选，并轮换检查部分已有来源。失败时保留上次成功的来源目录，不以空结果覆盖现有数据。

一次 `403`、`429`、超时或浏览器挑战不代表来源失效，应标记为 `restricted`。明确的 `404/410`、域名不存在或跨多个日期连续失败才进入 `unavailable`；确认来源永久撤回后才标记 `retired`。任何状态变化均可回滚。

## 6. 实时联网搜索

实时搜索不是从来源首页递归爬取整个网站，而是对具备明确检索方式的可信来源进行联合检索。

```text
用户主动选择“联网考据”或“事实核查”
  -> 展示将要发送的查询词和来源范围
  -> 本地规则或模型生成 1 至 3 个查询
  -> 选择 2 至 5 个相关且可用的来源
  -> 调用来源 API、站内搜索、Feed 或 Sitemap
  -> 合并、规范化并去重候选结果
  -> 临时读取排名靠前的 3 至 8 个页面
  -> 提取与查询命中位置相邻的有限片段
  -> 本地相关性重排和上下文预算裁剪
  -> 模型基于 WebEvidence 生成回答
  -> 程序校验引用并报告覆盖范围
  -> 丢弃临时网页正文
```

如果来源只提供 Sitemap，可以在本次请求中用标题和 URL 路径进行有限筛选，但不能下载整个站点建立长期索引。大型 Sitemap、无法服务端搜索的超大站点和纯 JavaScript 搜索页应直接降级为 `fetch-only` 或不支持搜索。

### 6.1 模型输入

模型只接收经过裁剪的结构化证据，不接收完整网页：

```json
{
  "sourceId": "museum-example",
  "title": "资料标题",
  "url": "https://example.org/item/123",
  "publisher": "来源机构",
  "retrievedAt": "2026-09-07T10:00:00Z",
  "excerpt": "与用户问题直接相关的短摘录",
  "trustLevel": "official",
  "contentHash": "sha256-of-response"
}
```

单页默认提供约 500 至 1,200 个中文字符，单次外部证据总预算建议控制在 4,000 至 8,000 tokens。URL、发布者、访问时间和哈希由程序生成；模型不能补写这些字段。API JSON 由 Rust 按 schema 解析，模型只负责查询规划、相关性判断、语义归一、冲突识别和基于证据的回答。

### 6.2 检索质量边界

没有外部正文索引会带来明确限制：

- 搜索质量依赖来源自身的 API 或站内检索能力。
- 每次搜索都需要网络访问，延迟和失败率高于本地检索。
- 只有 Sitemap 的大型站点无法做到低成本全文查询。
- 同一问题在不同时间可能得到不同结果，必须展示访问时间。
- 免费接口限额耗尽后只能返回已有部分结果，不能静默改用付费服务。

这些限制可以接受，因为目标是“少量可信来源的实时考据”，不是构建通用搜索引擎。

## 7. 抓取与可访问性检测

Rust `reqwest` 作为正常运行时 HTTP 客户端；不新增系统 `curl` 依赖。可以在诊断界面导出等价 curl 命令，但跨平台执行、超时、证书、重定向和错误映射均由 Rust 统一控制。

检测顺序如下：

1. DNS、TLS、目标 IP、协议和重定向安全检查。
2. 使用诚实可识别的 `Vinkey/<version>` User-Agent 发起小体积 GET；不单独依赖经常配置错误的 HEAD。
3. 校验状态码、Content-Type、JSON schema 或 HTML 特征。
4. 识别登录、验证码、Cloudflare/WAF、地区限制和 JavaScript 必需页面。
5. 对支持来源执行一次最小搜索或解析样本。

Basic、Bearer、API Key 和正式 OAuth 可以在后续按来源适配，凭据只进入系统凭据库。首期不访问需要网页登录的来源，不导入浏览器 Cookie。

Chromium 不进入首期正常检索链路。捆绑 Chromium 会显著增加安装体积、安全更新和跨平台维护成本，也不能可靠解决 WAF。后续若确有大量可信来源必须执行 JavaScript，可把它作为独立、可选的诊断或渲染 sidecar；遇到验证码时仍应停止并标记需要用户交互，不进行自动规避。

## 8. 安全与隐私

- 每次联网必须由用户显式触发，并展示查询词和目标来源。
- 不自动把完整选中文稿或未发布设定转换成外部查询。
- Rust 只允许访问来源记录中的 HTTPS origin 和 `allowedHosts`。
- DNS 解析后拒绝环回、私网、链路本地和其他保留地址，重定向后再次检查。
- 限制响应大小、超时、重定向次数、并发和单域请求频率。
- 网页文本始终视为不可信数据；其中的指令不得影响 Tool 调用、文件操作和系统 Prompt。
- 联网证据不自动写入项目记忆、人物资产、世界书或源文稿。
- 运行日志只记录来源 ID、状态、耗时和数量，不记录查询全文、网页正文或完整 Prompt。
- 对话可以保存用户可见的最终回答和引用元数据，不保存抓取到的完整网页正文。

## 9. Runtime 接入

新增独立任务合同，避免普通聊天静默联网：

```text
intent        research | fact-check
sideEffect    network
sourcePolicy  web-metadata | web-excerpts
tools         list_research_sources
              search_research_sources
              fetch_research_page
              verify_web_evidence
```

`TaskPolicy` 只有在用户显式点击联网入口或确认联网范围后才允许 `network`。`ToolGateway` 在每次调用时校验来源 ID、允许域名、请求预算、来源策略和响应 schema。当前普通聊天、项目分析和文档改写的 Tool allowlist 不获得联网能力。

Rust 服务建议拆分为：

- `SourceRegistryService`：冷启动目录、用户覆盖、状态历史和导入导出。
- `SourceDiscoveryService`：免费来源发现和候选归一。
- `SourceHealthService`：地址、搜索入口和访问状态检测。
- `ResearchSearchService`：有限来源联合检索、临时正文获取和取消。
- `WebEvidenceService`：片段裁剪、引用生成、去重和校验。

只持久化来源配置、健康状态、更新历史、搜索任务元数据和引用元数据，不创建外部正文表或外部全文索引。

## 10. 交互建议

设置页增加“可信来源”分区：

- 来源列表按机构类别、语言、地区、状态和来源方式过滤。
- 提供一键更新、添加来源、导入、导出和恢复内置项。
- 每个来源显示搜索能力、可信等级、最后检查时间和失败原因。
- 更新完成后展示新增、变更、受限和停用差异，而不是只提示数量。
- 用户覆盖的字段和主动停用状态在目录更新后继续生效。

对话输入区增加显式的联网控制，而不是新的常驻模式开关：

- “联网考据”：为普通研究问题提供外部证据。
- “事实核查”：以编辑器选区或用户陈述为核查目标。
- 发送前展示查询摘要和将访问的来源范围。
- 回答末尾展示已使用来源、未响应来源和证据不足项。

## 11. 验收指标

在进入开发前建立不少于 60 个文学创作研究问题的固定测试集，覆盖历史、地域、职业、制度、科技、文化、典籍和事实核查。对同一模型比较无联网和有联网两组结果。

首期建议门槛：

| 指标 | 目标 |
| --- | --- |
| Top 5 结果包含相关可信来源 | 不低于 70% |
| 展示引用可重新访问且指向实际来源 | 不低于 95% |
| 关键事实有摘录支持或明确标记未核实 | 不低于 90% |
| 有证据回答相对无联网回答的事实错误 | 降低至少 30% |
| 搜索准备阶段 p95，排除模型生成 | 不超过 12 秒 |
| 单一来源失败 | 返回部分结果，不导致任务整体失败 |
| 普通创作请求未获授权联网 | 100% 阻止 |
| 更新任务 | 不保存外部网页正文或建设外部全文索引 |

如果事实错误没有显著下降，或者大多数测试问题无法从来源列表中取得可引用证据，不应继续扩大 UI 和 Agent 能力，应先改善来源覆盖与适配器质量。

## 12. 版本计划与工作量

### 阶段 A：来源管理

- 冷启动来源目录、来源 schema 和 SQLite 状态。
- 一键更新、免费额度预算、候选校验、软停用和回滚。
- 用户编辑、启停、导入导出及目录覆盖规则。
- 预计单人 2 至 3 周。

### 阶段 B：实时检索闭环

- MediaWiki、JSON API、RSS、Sitemap 和有限 HTML Search 适配器。
- 查询规划、来源路由、结果去重、临时页面提取和证据组装。
- 显式联网授权、流式状态、取消、部分失败和引用 UI。
- 预计单人 3 至 5 周。

### 阶段 C：质量与安全加固

- SSRF、重定向、限流、恶意页面和 Prompt Injection 测试。
- 来源可达性矩阵、失败恢复、引用校验和固定评测集。
- 按评测结果扩充少量高价值来源，不追求来源数量。
- 预计单人 2 至 4 周。

首期总工作量预计为单人 7 至 12 周，不包含 Chromium、登录态网站、通用搜索引擎抓取或外部正文索引。建议在阶段 B 完成后进行 Go/No-Go 评审；只有研究型任务达到验收门槛，才将该能力从候选功能提升为稳定功能。
