# Vinkey UI 设计方案

- 状态：已确定，作为首版 UI 实现基线
- 日期：2026-08-31
- 适用端：Windows、macOS 桌面应用

## 1. 设计结论

Vinkey 采用 **深色、安静、AI 对话优先的左右双栏桌面创作工作台**。

该布局基于当前产品的实际操作权重：用户通过多轮 AI 对话完成构思、续写、改稿和设定梳理的频率，高于直接手动编辑文件的频率。因此右侧内容区默认显示 AI 对话，文件编辑作为同一内容区内的独立页面存在。

参考页面中“全局导航 + 项目文件树 + 主工作区 + 辅助面板”的结构适合桌面创作工具，但 Vinkey 调整其信息优先级：

- 左侧由图标工具轨和工作区文件面板组成，负责全局导航、文件浏览、搜索和会话历史。
- 右侧是统一内容区，右上固定提供“对话 / 文件”页面切换按钮，两个页面互斥显示。
- 右侧默认进入“对话”页；打开左侧文档后自动切换到“文件”页。
- Markdown 在“文件”页内以“编辑 / 分栏 / 预览”切换；TXT 使用纯文本编辑器。
- 全局导航压缩为图标工具轨，去掉与本地产品无关的容量、商城和升级入口。
- AI 生成结果不使用阻塞式居中弹窗，改为可审核的内联差异面板。

## 2. 设计原则

### 2.1 AI 对话优先

打开工作区后，视觉焦点落在右侧“对话”页的对话记录、上下文文件和提示输入上。AI 对话是构思、续写、改稿和设定梳理的主要入口；切换到“文件”页后查看素材、人工修订和确认产出。界面不使用营销式欢迎页、大标题、装饰图形或大量悬浮卡片。

### 2.2 本地状态可见

当前工作区、文件相对路径、保存状态、当前模型和附加上下文必须清晰可见。不用“已同步”等云产品语言表达本地保存。

### 2.3 AI 操作可审核

AI 可以回答、生成草稿和提交修改建议，但不得无提示覆盖正文。修改类结果必须显示差异，并由用户选择接受、拒绝或继续调整。

### 2.4 稳定不跳动

工具栏、图标按钮、标签页、状态栏和输入区使用稳定尺寸。流式输出、文件名变化和状态标记不得导致主布局频繁位移。

### 3.1 Windows 与 macOS 主界面差异

两端共用相同的工具轨、工作区文件面板和右侧内容区，不改变功能位置与操作流程。平台差异集中在系统标题栏和窗口控制区域：

| 项目 | Windows | macOS |
| --- | --- | --- |
| 窗口控制 | 最小化、最大化/还原、关闭按钮位于标题栏右侧 | 红黄绿“交通灯”位于标题栏左侧 |
| 标题栏内容 | 左侧显示应用图标和工作区标题；右侧为系统窗口按钮 | 工作区标题居中；左侧为系统窗口按钮，不显示应用图标 |
| 可拖动区域 | 标题与窗口按钮之间的空白区域可拖动，双击切换最大化/还原 | 标题栏空白区域可拖动，双击行为跟随系统设置 |
| 布局安全区 | 标题栏右侧不得放置应用操作，避免与窗口按钮冲突 | 标题栏左侧至少预留系统交通灯区域；全屏时允许系统接管标题栏表现 |

- 首版使用原生标题栏，不把“对话 / 文件”、模型选择、新建会话等应用操作放入标题栏。
- 标题栏以下的主界面从同一垂直位置开始；Windows 不因右侧窗口按钮压缩内容，macOS 不因左侧交通灯缩进工具轨。
- 窗口最大化、全屏和退出全屏均由系统处理，主界面只根据可用内容尺寸执行第 8 节的自适应规则。
- 截图、原型和验收用例应分别呈现对应平台的原生窗口外观，不在任一平台仿制另一平台的窗口控件。

### 3.2 工具轨

工具轨默认宽度 48px，只使用 Lucide 图标，不放置长文字导航。

| 位置 | 命令 | 图标 |
| --- | --- | --- |
| 顶部 | 工作区文件 | Files |
| 顶部 | 全局搜索 | Search |
| 顶部 | 历史会话 | MessagesSquare |
| 底部 | 模型与应用设置 | Settings |

每个图标按钮为 32 × 32px，图标为 16px，悬停显示文字提示。当前模块使用左侧 2px 强调线和浅色图标，不使用大面积彩色底。

### 3.3 工作区文件面板

- 默认宽度 260px，允许在 220-360px 内拖动调整。
- 头部显示工作区名，右侧提供新建文件、新建文件夹、刷新和更多菜单。
- 文件树默认展示 Markdown 和 TXT；其他文件可选择显示，但不自动读取内容。
- 文件类型使用 FileText、FileType、Folder、FolderOpen 图标，不使用 emoji。
- 当前文件行使用中性选中底色和左侧强调线。
- 未保存文件显示固定尺寸圆点，不改变行宽。
- 删除需要确认并优先移入系统回收站。

### 3.4 右侧“对话”页

- 右侧内容区使用剩余弹性空间，最小宽度 480px，不设置固定最大宽度。
- 内容区顶部右侧固定显示“对话 / 文件”分段按钮；“对话”为默认选中状态。
- 头部包含会话选择、新建会话、当前模型和连接状态。
- 上下文文件位于消息流上方的独立水平条中，每个文件显示为可移除标签。
- 消息流是“对话”页的主要滚动容器。AI 消息使用无边框文本块；用户消息使用弱底色区分，不把所有消息做成卡片。
- AI 返回的文档修改提案在消息中显示摘要和目标文件；需要查看文档时切换到“文件”页打开审核视图。
- 输入区固定在“对话”页底部，高度在 96-220px 之间随内容增长。
- 输入区提供附件、创作模式菜单和发送按钮。
- 生成期间发送按钮变为固定尺寸的停止图标，避免布局变化。
- “对话”页不提供常规收起操作；进入设置等全局页面时才由对应页面临时替换。

### 3.5 右侧“文件”页

“文件”页与“对话”页共用右侧内容区，不再以独立并行面板或抽屉出现。未打开文档时显示空状态，提示用户从左侧工作区选择文档；打开文档后自动展示当前活动文件。

内容区按以下顺序排列：

1. 36px 文档标签栏：文件图标、文件名、未保存标记、关闭图标。
2. 40px 文件工具栏：相对路径、保存、视图切换和返回“对话”页。
3. 可伸缩编辑区：CodeMirror 源文本和可选 Markdown 预览。
4. 24px 状态栏：行列、字符数、字数、UTF-8、LF/CRLF 和保存状态。

编辑视图使用三段式切换：

- **编辑**：单栏 CodeMirror，默认视图。
- **分栏**：编辑器和 Markdown 预览各占一半。
- **预览**：单栏阅读视图。

模式切换使用紧凑分段控件。TXT 文件禁用预览模式。后续增加 PDF、图片等只读格式时，该页面切换为对应预览器，不改变对话数据。

## 4. 核心交互流程

### 4.1 首次打开

应用首屏仍是工作台壳层，不是落地页：

- 文件面板显示“打开文件夹”主操作。
- 右侧“对话”页显示最近会话、建议创作入口和提示输入区。
- 未配置模型时在“对话”页提供“添加模型”命令；配置完成后可直接开始不依赖文件的构思对话。
- 右侧顶部的“对话”按钮默认选中；打开文件或创建文稿后自动切换到“文件”页。

### 4.2 打开与保存文档

1. 点击文件树中的文稿，在右侧“文件”页中新建或聚焦标签页；页面自动从“对话”切换到“文件”。
2. 编辑后，标签页和状态栏显示未保存状态。
3. 保存成功只更新原位状态，不弹出成功通知。
4. 外部程序改变文件时，在文档工具栏显示持久冲突条。
5. 冲突条提供对比、重新加载和另存为，不静默覆盖。

### 4.3 附加上下文

支持三种方式：

- 从文件树拖入右侧“对话”页。
- 在文件树右键选择“添加到当前会话”。
- 通过 AI 输入区的 Paperclip 图标选择文件。

附加后显示文件名、大小和上下文占用估算。只有上下文条中明确列出的文件才随请求发送给模型。

### 4.4 AI 改稿审核

    AI 返回修改提案
            │
            ├─ 普通回答 → 留在消息流，可复制或插入光标处
            │
            └─ 文档修改 → 切换右侧“文件”页并打开 diff 审核视图
                             │
                             ├─ 接受全部
                             ├─ 逐块接受或拒绝
                             ├─ 放弃提案
                             └─ 返回会话继续调整

diff 不只依赖红绿色：删除行同时使用 Minus 图标和左边标，新增行使用 Plus 图标和左边标。审核期间可随时切回“对话”页继续要求 AI 调整，未保存状态和会话数据均保留。

### 5.2 字体与字号

- UI 字体：system-ui、-apple-system、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif。
- 编辑字体：默认跟随 UI 字体，设置中允许选择等宽或本机字体。
- 代码和 Markdown 标记：ui-monospace、SFMono-Regular、Consolas、monospace。
- UI 常规字号 13px，面板标题 13px/600，辅助文字 12px。
- 编辑正文默认 16px，行高 1.8，用户可调整。
- 所有文字使用零字距，字号不随视口宽度缩放。

### 5.3 尺寸、间距与圆角

- 基础间距网格为 4px，常用间距为 4、8、12、16、24px。
- 图标按钮为 28px 或 32px，图标 16px。
- 常规输入框高 32px；多行会话输入自适应高度。
- 常驻面板不用悬浮卡片外观，直接以 1px 分隔线组织。
- 菜单、输入框、消息弱底色块圆角 6px。
- 对话框和真正浮层圆角 8px，不使用超大圆角。

### 5.4 阴影和动效

- 常驻面板无阴影，仅菜单、对话框和拖动浮层使用阴影。
- 微交互时长 120-180ms，面板展开收起 180-220ms。
- 流式 AI 内容只追加文字，不为每个 token 添加动画。
- 遵循系统“减少动态效果”偏好。

## 6. 组件规范

### 6.1 按钮

- 保存、撤销、重做、附件、刷新、收起面板等熟悉命令使用 Lucide 图标按钮和 tooltip。
- “打开文件夹”“接受全部”“另存为”等明确命令使用图标加文字。
- 同一操作区只有一个主按钮。
- 危险操作不使用主强调色。

### 6.2 标签和状态

- 文档上下文标签使用文件图标、截断文件名和移除图标。
- 连接状态使用状态点加模型名，不只依赖颜色。
- 标签高度固定为 24px，长文件名省略，悬停显示完整相对路径。

### 6.3 菜单和对话框

- 文件操作、视图选项和模型选择使用菜单。
- 设置使用独立页面，不塞入多层弹窗。
- 只有删除、放弃未保存修改、覆盖外部变更等阻断决策使用对话框。

### 6.4 通知

- 保存成功和连接成功不弹 toast，只更新原位状态。
- 可恢复的失败使用面板内联提示并提供重试。
- 跨面板且不需要立即决策的结果才使用右下角 toast。

## 7. 主要页面和状态

### 7.1 工作台

工作台是默认页，由左侧工具轨、工作区文件面板和右侧统一内容区组成。右侧内容区通过顶部“对话 / 文件”按钮切换页面，不设置单独首页仪表盘。

### 7.2 搜索

搜索复用左侧面板，不覆盖右侧内容区。结果按文件分组，显示相对路径、匹配行和简短摘要，点击后在右侧“文件”页打开文件并定位到对应行。

### 7.3 会话历史

会话历史复用左侧面板，显示标题、更新时间、模型和上下文数量。选择会话后切换到右侧“对话”页，恢复消息和上下文；“文件”页的活动文档保持不变。

### 7.4 设置

设置临时替换右侧内容区，作为完整工作区页面打开，左侧工具轨保留，设置页内部使用分组导航：

- 通用：主题、语言、启动和更新。
- 编辑器：字体、字号、行高、自动换行和自动保存。
- 模型：Ollama 和 OpenAI 兼容提供商、地址、模型和连接测试。
- 数据：会话数据位置、导出、删除和日志。
- 权限：已授权工作区及撤销授权。

### 7.5 空态与错误态

| 状态 | 表现 |
| --- | --- |
| 未选工作区 | 打开文件夹按钮 + 最近工作区 |
| 工作区为空 | 新建 Markdown、新建 TXT 两个明确命令 |
| 未打开文档 | 右侧“文件”页显示选择文档的空状态，“对话”页保持可用 |
| 未配置模型 | 右侧“对话”页显示“添加模型”命令 |
| 模型不可用 | 头部状态点 + 内联错误 + 重试 |
| 文件无权限 | 保留当前草稿，提供重新授权或另存为 |
| 上下文超限 | 标出超额文件，禁用发送并提供移除 |

## 8. 窗口和自适应

- 右侧内容区最小宽度 480px，是窗口收缩时最后被压缩的区域。
- 窗口足够宽时同时显示左侧工具轨、工作区文件面板和右侧内容区；右侧只显示“对话”或“文件”其中一个页面。
- 宽度不足时优先隐藏工作区文件面板，保留工具轨和右侧内容区。
- 小窗口中打开文件后仍使用右侧“文件”页，不额外创建抽屉或覆盖层；顶部切换按钮始终可用。
- 不同时以覆盖层展示文件树和内容页面。
- 右侧内容区宽度跟随窗口弹性调整，不单独记录编辑器面板宽度。

## 9. 平台一致性

- 首版使用系统原生标题栏和窗口控制，不模拟 macOS 交通灯或 Windows 窗口按钮。
- 通用布局、功能和颜色保持一致，快捷键使用平台对应修饰键。
- 文件选择、保存、右键菜单、回收站和凭据库使用操作系统原生能力。
- 不在主界面固定展示 Ctrl 或 Cmd 提示；命令显示在系统菜单和对应 tooltip 中。

## 10. 无障碍与输入

- 所有交互元素均可键盘访问，焦点轮廓使用 2px 强调色。
- 文字和背景至少满足 WCAG AA，状态不只通过颜色区分。
- 支持中文 IME 组合输入，组字期间不触发发送、保存或 AI 操作。
- 文本缩放后工具栏、标签和状态栏不重叠。
- 长文件名可省略，但不得挤压图标按钮。
- 鼠标拖动操作必须提供菜单或按钮等价路径。

## 11. 实现顺序

1. 建立深色/浅色设计 token、字体和基础控件。
2. 实现工具轨、文件面板和左右双栏工作台的右侧统一内容区。
3. 实现右侧“对话”页的上下文文件条、消息流和自适应输入区。
4. 实现右侧“文件”页的文档标签页、CodeMirror、预览器、视图切换和状态栏，以及顶部“对话 / 文件”切换。

7. 在 Windows 和 macOS 上执行键盘、IME、缩放、高对比度和小窗口验收。

## 12. UI 验收标准

- 应用启动后直接进入可操作工作台，不出现营销首页。
- 在 1440 × 900、1280 × 800 和 1024 × 680 三组窗口下无文字、面板和按钮重叠。
- 右侧内容区始终是最大、最稳定的可见区域，默认打开“对话”页。
- 打开文件时自动切换到右侧“文件”页，不创建并行编辑器面板；切回“对话”页后会话仍保持。
- 熟悉工具命令使用 Lucide 图标，陌生图标均有 tooltip。
- 文件名、模型名和上下文标签在窄宽度下不会挤出容器。
- AI 发送前可看到全部附加上下文，AI 修改写入前必须经过审核。
- 未保存、已保存、外部冲突和无权限状态可被清楚区分。
- 深色与浅色主题均通过对比度、键盘焦点和中文 IME 测试。
