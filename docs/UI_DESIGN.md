# Vinkey UI 设计方案

- 状态：已确定，作为首版 UI 实现基线
- 日期：2026-08-31
- 适用端：Windows、macOS 桌面应用

## 1. 设计结论

Vinkey 采用 **深色、安静、AI 对话优先的左右双栏桌面创作工作台**。

该布局基于当前产品的实际操作权重：用户通过多轮 AI 对话完成构思、续写、改稿和设定梳理的频率，高于直接手动编辑文件的频率。因此右侧内容区默认显示 AI 对话，文件编辑作为同一内容区内的独立页面存在。

参考 ClaudeCodeUI 的“会话导航 + 工作区标签 + 侧向编辑器”模式，Vinkey 按文学创作场景收敛为：

- 左侧是固定会话栏，负责工作区识别、新建会话、统一搜索、会话历史和设置入口；需要专注设置或扩大内容区时，可折叠为窄图标栏。
- 右侧是统一内容区，右上固定提供“对话 / 文件”页面切换按钮，两个页面互斥显示。
- 右侧默认进入“对话”页；点击“文件”先显示工作区文件列表，选择文档后再在文件列表右侧展开编辑器。
- Markdown 在侧向编辑器内以“编辑 / 分栏 / 预览”切换；TXT 使用纯文本编辑器。
- 不引入 ClaudeCodeUI 的 Shell、Git、Tasks、Browser 和插件入口，避免把创作工作台扩展成通用 IDE。
- AI 生成结果不使用阻塞式居中弹窗，改为可审核的内联差异面板。

## 2. 设计原则

### 2.1 AI 对话优先

打开工作区后，视觉焦点落在右侧“对话”页的对话记录、上下文文件和提示输入上。AI 对话是构思、续写、改稿和设定梳理的主要入口；切换到“文件”页后查看素材、人工修订和确认产出。界面不使用营销式欢迎页、大标题、装饰图形或大量悬浮卡片。

### 2.2 本地状态可见

当前工作区、文件相对路径、保存状态、当前模型和附加上下文必须清晰可见。不用“已同步”等云产品语言表达本地保存。

### 2.3 AI 操作可审核

AI 可以回答、生成草稿和提交修改建议，但不得无提示覆盖正文。修改类结果必须显示差异，并由用户选择接受、拒绝或继续调整。

### 2.4 稳定不跳动

工具栏、图标按钮、标签页、状态栏和输入区使用稳定尺寸。流式输出、文件名变化和状态标记不得导致主布局频繁位移。

### 3.1 Windows 与 macOS 主界面差异

为避免概念混淆，本文将“文件 / 编辑 / 查看 / 窗口 / 帮助”等命令入口称为**应用菜单栏**，将工作区标题、拖动区域和窗口控制所在区域称为**窗口标题区**。两端共用相同的左侧会话栏和右侧内容区，但应用菜单栏和窗口标题区采用明显不同的平台布局。

| 项目 | Windows | macOS |
| --- | --- | --- |
| 应用菜单栏 | 位于 Vinkey 窗口内最上方的自绘标题栏中 | 由 macOS 响应到屏幕最上方的系统全局菜单栏，不占用 Vinkey 窗口内容高度 |
| 窗口标题区 | 窗口顶部固定显示 36px 自绘标题栏，包含品牌、当前工作区、当前模型、应用菜单、拖动区和窗口控制 | 使用原生 Overlay 标题栏；WebView 延伸至窗口顶端，内容区上方不再显示独立标题栏 |
| 窗口控制 | 自绘最小化、最大化/还原和关闭按钮，固定在标题栏右侧 | 使用原生红黄绿“交通灯”，叠放在左侧会话栏顶部 |
| 左侧会话栏 | 从 36px 自绘标题栏下方开始 | 从窗口顶端开始，头部预留 42px 交通灯安全区 |
| 主界面起点 | 会话栏和右侧内容区从 36px 标题栏下方开始 | 会话栏和右侧内容区从窗口内容顶端开始 |
| 拖动与全屏 | 标题栏空白区域可拖动，双击切换最大化/还原 | 拖动、缩放和全屏行为由原生窗口标题区及系统处理 |

Windows 主界面纵向结构：

    Vinkey 自绘标题栏（36px）：品牌 / 工作区 / 模型 / 应用菜单 / 拖动区 / 窗口控制
    左侧会话栏 + 右侧内容区

macOS 主界面纵向结构：

    macOS 屏幕顶部系统菜单栏：Vinkey / 文件 / 编辑 / 查看 / 窗口 / 帮助（位于应用窗口之外）
    Vinkey 窗口：Overlay 交通灯 + 左侧会话栏 / 右侧内容区

- Windows 自绘应用菜单和 macOS 原生系统菜单提供一致的命令集合，但菜单排版、快捷键显示和展开行为遵循各自平台规范。
- “对话 / 文件”等页面内操作仍位于右侧内容区，不因平台菜单位置不同而改变。
- 截图、原型和验收用例必须分别呈现两种纵向结构，不能用同一套窗口顶部布局代替。

### 3.2 左侧会话栏

- 默认宽度 288px；窗口宽度低于 1180px 时收窄至 248px。会话栏支持手动折叠为 52px 窄图标栏，折叠后保留品牌图标、展开按钮和设置入口。
- 头部依次显示品牌、工作区名称与路径、工作区切换/刷新、新建会话、折叠按钮和统一搜索框。
- 搜索同时匹配会话标题与 Markdown/TXT 正文；结果仍在会话栏内显示，点击文档结果切换到“文件”页并展开编辑器。
- 主体显示最近会话，当前会话使用中性选中底色；标题、消息数和更新时间均可扫描。
- “模型与应用设置”固定在会话栏底部。设置页打开时自动折叠会话栏，以释放完整配置所需的横向空间；关闭设置后恢复进入前的会话栏状态。
- 如果用户在设置页中手动展开或折叠会话栏，关闭设置时保留该次手动操作，不被自动恢复逻辑覆盖。
- 手动折叠状态作为本机界面偏好保存；设置页触发的临时自动折叠不改写该偏好。
- macOS 会话栏头部额外预留 42px 交通灯安全区，Windows 不增加该留白。

### 3.3 右侧“对话”页

- 右侧内容区使用剩余弹性空间，最小宽度 480px，不设置固定最大宽度。
- 内容区顶部只保留一条统一顶栏。左侧分两行显示会话摘要标题，以及“项目名 · 当前模型”；右侧固定显示“对话 / 文件”分段按钮，“对话”为默认选中状态。
- 统一顶栏下方直接进入消息流，不重复显示“AI 对话区”标题，也不设置独立的顶部上下文条；会话选择与新建会话归左侧项目/会话栏负责。
- 消息流是“对话”页的主要滚动容器。AI 消息左对齐并使用无边框文本块；用户消息右对齐并使用弱底色气泡，不把所有消息做成卡片。
- 每条用户和 AI 消息下方显示复制操作与消息时间；流式生成中的 AI 消息在原条目内显示生成状态，不额外创建重复条目。
- AI 返回的文档修改提案在消息中显示摘要和目标文件；需要查看文档时切换到“文件”页打开审核视图。
- 输入区固定在“对话”页底部，高度在 96-220px 之间随内容增长。
- 已引用文件显示在输入框上部，可逐项移除。后续通过输入 `@` 搜索并引用文件，不保留单独的回形针入口。
- 输入区底部左侧提供模型切换，右侧显示上下文占用和发送按钮，不设置“创作模式”按钮。
- 生成期间发送按钮变为固定尺寸的停止图标，避免布局变化。
- “对话”页不提供常规收起操作；进入设置等全局页面时才由对应页面临时替换。

### 3.4 右侧“文件”页

“文件”页与“对话”页共用右侧内容区。每次从顶部标签进入“文件”页时，先显示占满内容区的工作区文件列表；选择文档后，文件列表收窄至 260-340px，编辑器在其右侧展开。收起编辑器后保留文件列表，不自动返回对话。

文件列表头部显示工作区名称和路径，并提供新建文件、新建文件夹与刷新；下方提供文件名筛选。文件类型使用 FileText、FileType、Folder、FolderOpen 图标，不使用 emoji。当前文件行使用中性选中底色和左侧强调线。

内容区按以下顺序排列：

1. 36px 文档标签栏：文件图标、文件名、未保存标记、关闭图标。
2. 40px 文件工具栏：相对路径、保存、视图切换和返回“对话”页。
3. 可伸缩编辑区：CodeMirror 源文本和可选 Markdown 预览。
4. 24px 状态栏：行列、字符数、字数、UTF-8、LF/CRLF 和保存状态。

编辑视图使用三段式切换：

- **编辑**：单栏 CodeMirror，默认视图。
- **分栏**：编辑器和 Markdown 预览各占一半。
- **预览**：单栏阅读视图。

模式切换使用紧凑分段控件。TXT 文件禁用预览模式。后续增加 PDF、图片等只读格式时，该页面切换为对应预览器，不改变对话数据。

## 4. 核心交互流程

### 4.1 首次打开

应用首屏仍是工作台壳层，不是落地页：

- 左侧会话栏显示“打开工作区”入口；进入右侧“文件”页后，文件列表显示“打开文件夹”主操作。
- 右侧“对话”页显示最近会话、建议创作入口和提示输入区。
- 未配置模型时在“对话”页提供“添加模型”命令；配置完成后可直接开始不依赖文件的构思对话。
- 右侧顶部的“对话”按钮默认选中；点击“文件”先显示文件列表，打开或创建文稿后再在列表右侧展开编辑器。

### 4.2 打开与保存文档

1. 点击顶部“文件”进入文件列表，再点击列表中的文稿，在列表右侧新建或聚焦编辑标签页；从搜索结果或新建文稿进入时自动完成页面切换。
2. 编辑后，标签页和状态栏显示未保存状态。
3. 保存成功只更新原位状态，不弹出成功通知。
4. 外部程序改变文件时，在文档工具栏显示持久冲突条。
5. 冲突条提供对比、重新加载和另存为，不静默覆盖。
6. 点击“收起编辑器”只关闭侧向编辑器，文件列表继续保持可见。

### 4.3 附加上下文

当前从“文件”页右键文档添加到会话上下文。后续在输入框中输入 `@` 时显示工作区文件候选，并允许键盘筛选和选择；不设置独立的 Paperclip 图标。

引用后，文件名显示在输入框上部并可逐项移除，输入框底部继续显示上下文占用估算。只有输入框上部明确列出的文件才随请求发送给模型。

### 4.4 AI 改稿审核

    AI 返回修改提案
            │
            ├─ 普通回答 → 留在消息流，可复制或插入光标处
            │
            └─ 文档修改 → 切换右侧“文件”页并打开 diff 审核视图
                             │
                             ├─ 接受全部
                             ├─ 逐块接受或拒绝
                             ├─ 放弃提案
                             └─ 返回会话继续调整

diff 不只依赖红绿色：删除行同时使用 Minus 图标和左边标，新增行使用 Plus 图标和左边标。审核期间可随时切回“对话”页继续要求 AI 调整，未保存状态和会话数据均保留。

### 5.2 字体与字号

- UI 字体：system-ui、-apple-system、Segoe UI、PingFang SC、Microsoft YaHei、sans-serif。
- 编辑字体：默认跟随 UI 字体，设置中允许选择等宽或本机字体。
- 代码和 Markdown 标记：ui-monospace、SFMono-Regular、Consolas、monospace。
- UI 常规字号 13px，面板标题 13px/600，辅助文字 12px。
- 编辑正文默认 16px，行高 1.8，用户可调整。
- 所有文字使用零字距，字号不随视口宽度缩放。

### 5.3 尺寸、间距与圆角

- 基础间距网格为 4px，常用间距为 4、8、12、16、24px。
- 图标按钮为 28px 或 32px，图标 16px。
- 常规输入框高 32px；多行会话输入自适应高度。
- 常驻面板不用悬浮卡片外观，直接以 1px 分隔线组织。
- 菜单、输入框、消息弱底色块圆角 6px。
- 对话框和真正浮层圆角 8px，不使用超大圆角。

### 5.4 阴影和动效

- 常驻面板无阴影，仅菜单、对话框和拖动浮层使用阴影。
- 微交互时长 120-180ms，面板展开收起 180-220ms。
- 流式 AI 内容只追加文字，不为每个 token 添加动画。
- 遵循系统“减少动态效果”偏好。

## 6. 组件规范

### 6.1 按钮

- 保存、撤销、重做、附件、刷新、收起面板等熟悉命令使用 Lucide 图标按钮和 tooltip。
- “打开文件夹”“接受全部”“另存为”等明确命令使用图标加文字。
- 同一操作区只有一个主按钮。
- 危险操作不使用主强调色。

### 6.2 标签和状态

- 文档上下文标签使用文件图标、截断文件名和移除图标。
- 连接状态使用状态点加模型名，不只依赖颜色。
- 标签高度固定为 24px，长文件名省略，悬停显示完整相对路径。

### 6.3 菜单和对话框

- 文件操作、视图选项和模型选择使用菜单。
- 设置使用独立页面，不塞入多层弹窗。
- 只有删除、放弃未保存修改、覆盖外部变更等阻断决策使用对话框。

### 6.4 通知

- 保存成功和连接成功不弹 toast，只更新原位状态。
- 可恢复的失败使用面板内联提示并提供重试。
- 跨面板且不需要立即决策的结果才使用右下角 toast。

## 7. 主要页面和状态

### 7.1 工作台

工作台是默认页，由左侧会话栏和右侧统一内容区组成。右侧内容区通过顶部“对话 / 文件”按钮切换页面，不设置单独首页仪表盘。

### 7.2 搜索

统一搜索固定在会话栏顶部，不覆盖右侧内容区。结果同时包含匹配的会话标题和文档正文；文档结果显示相对路径、匹配行和简短摘要，点击后切换到右侧“文件”页并展开对应文档编辑器。

### 7.3 会话历史

会话历史常驻左侧会话栏，显示标题、更新时间、消息数等摘要。选择会话后切换到右侧“对话”页，恢复消息和上下文；已经打开的文档状态保持不变。

### 7.4 设置

设置入口固定在会话栏底部。设置页临时替换右侧内容区；打开设置时会话栏自动折叠为窄图标栏，设置页内部使用分组导航：

- 设置页右上角提供“返回工作区”关闭入口；`Esc` 可作为辅助关闭方式。
- 进入设置前记录会话栏的展开/折叠状态。关闭设置时默认恢复该状态；设置期间用户手动切换会话栏后，以用户最后状态为准。

- 通用：主题、语言、启动和更新。
- 编辑器：字体、字号、行高、自动换行和自动保存。
- 模型：Ollama 和 OpenAI 兼容提供商、地址、模型和连接测试。
- 数据：会话数据位置、导出、删除和日志。
- 权限：已授权工作区及撤销授权。

### 7.5 空态与错误态

| 状态 | 表现 |
| --- | --- |
| 未选工作区 | 打开文件夹按钮 + 最近工作区 |
| 工作区为空 | 新建 Markdown、新建 TXT 两个明确命令 |
| 未打开文档 | 右侧“文件”页显示完整文件列表，选择文档后才展开编辑器；“对话”页保持可用 |
| 未配置模型 | 右侧“对话”页显示“添加模型”命令 |
| 模型不可用 | 头部状态点 + 内联错误 + 重试 |
| 文件无权限 | 保留当前草稿，提供重新授权或另存为 |
| 上下文超限 | 标出超额文件，禁用发送并提供移除 |

## 8. 窗口和自适应

- 右侧内容区最小宽度 480px，是窗口收缩时最后被压缩的区域。
- 窗口足够宽时同时显示 288px 左侧会话栏和右侧内容区；右侧只显示“对话”或“文件”其中一个页面。
- 窗口宽度低于 1180px 时会话栏收窄至 248px；低于 900px 时收窄至 232px，但搜索、会话和设置入口仍保持可用。
- 会话栏折叠时应用布局使用 52px 窄图标栏；设置页打开会自动进入该状态，关闭后按进入前状态或用户在设置期间的手动操作恢复。
- “文件”页未选文档时文件列表占满右侧；选中文档后，文件列表收窄至 260-340px，编辑器占用剩余空间。
- 900px 以下的小窗口隐藏文件列表并让编辑器占满右侧；收起编辑器后恢复完整文件列表，不创建抽屉或覆盖层。
- 顶部“对话 / 文件”切换按钮始终可用，右侧内容区宽度跟随窗口弹性调整。

## 9. 平台一致性

- Windows 使用 36px 自绘标题栏、应用菜单和窗口控制；macOS 使用原生 Overlay 标题栏、交通灯和屏幕顶部系统菜单栏。
- 两端保持命令能力、内容区布局和颜色一致，不要求窗口顶部结构一致；快捷键使用平台对应修饰键。
- 文件选择、保存、右键菜单、回收站和凭据库使用操作系统原生能力。
- 不在主界面固定展示 Ctrl 或 Cmd 提示；命令显示在对应平台的应用菜单和 tooltip 中。

## 10. 无障碍与输入

- 所有交互元素均可键盘访问，焦点轮廓使用 2px 强调色。
- 文字和背景至少满足 WCAG AA，状态不只通过颜色区分。
- 支持中文 IME 组合输入，组字期间不触发发送、保存或 AI 操作。
- 文本缩放后工具栏、标签和状态栏不重叠。
- 长文件名可省略，但不得挤压图标按钮。
- 鼠标拖动操作必须提供菜单或按钮等价路径。

## 11. 实现顺序

1. 建立深色/浅色设计 token、字体和基础控件。
2. 实现左侧会话栏和右侧统一内容区，并将搜索和设置分别固定在会话栏顶部与底部。
3. 实现右侧“对话”页的统一顶栏、左右消息流、消息操作和带引用文件区的自适应输入框。
4. 实现右侧“文件”页的文件列表、侧向编辑器、文档标签页、CodeMirror、预览器、视图切换和状态栏，以及顶部“对话 / 文件”切换。
5. 实现 AI 修改 diff 审核面板和文档冲突状态。
6. 补齐空态、加载、断线、超时、无权限和上下文超限状态。
7. 在 Windows 和 macOS 上执行键盘、IME、缩放、高对比度和小窗口验收。

## 12. UI 验收标准

- 应用启动后直接进入可操作工作台，不出现营销首页。
- 在 1440 × 900、1280 × 800 和 1024 × 680 三组窗口下无文字、面板和按钮重叠。
- 右侧内容区始终是最大、最稳定的可见区域，默认打开“对话”页。
- 点击顶部“文件”先看到完整文件列表；选择文档后编辑器在列表右侧展开，收起编辑器后仍停留在文件列表。
- 从搜索结果或新建文稿打开文件时自动切换到“文件”页；切回“对话”页后会话仍保持。
- 熟悉工具命令使用 Lucide 图标，陌生图标均有 tooltip。
- 文件名、模型名和上下文标签在窄宽度下不会挤出容器。
- AI 发送前可看到全部附加上下文，AI 修改写入前必须经过审核。
- 未保存、已保存、外部冲突和无权限状态可被清楚区分。
- 左侧会话栏可通过图标按钮折叠和展开；进入设置自动折叠，关闭设置后正确恢复进入前状态，设置期间的手动切换优先。
- 深色与浅色主题均通过对比度、键盘焦点和中文 IME 测试。
