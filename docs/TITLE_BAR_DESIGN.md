# Vinkey 系统标题栏与功能菜单设计

- 状态：实现基线
- 日期：2026-08-31
- 适用端：Tauri 2 Windows / macOS 桌面应用

## 1. 目标

标题栏是应用级操作的稳定入口，负责承载窗口管理、当前工作区识别和高频命令。它不重复左侧工具轨或对话工具栏的内容，也不承载营销、账号或云端存储入口。

本次升级包括：

1. 所有应用级菜单统一使用中文。
2. 标题栏菜单可直接执行新建会话、打开工作区、新建文档、保存、页面切换、主题切换和模型设置。
3. Windows 和 macOS 均提供最小化、最大化/还原、关闭按钮；标题栏中间区域支持拖拽移动窗口，双击切换最大化。
4. 菜单显示平台常用快捷键，命令仍由应用状态驱动，避免菜单和工具栏状态不一致。

## 2. 竞品与同类应用观察

对比豆包、WorkBuddy 等本地 AI 应用，以及 VS Code、ChatGPT 桌面端等成熟工作台，可以归纳出标题栏的通用设计：

| 共性 | 豆包 / WorkBuddy 等 AI 应用的常见做法 | Vinkey 的取舍 |
| --- | --- | --- |
| 应用身份 | 左侧保留产品名或图标，始终可见 | 使用 V 图标、Vinkey 和当前工作区名；模型名作为弱化状态信息 |
| 快速入口 | 新建会话、搜索、设置等高频操作靠近标题栏或首屏 | 新建会话放入“文件”菜单，搜索保留在左侧工具轨，设置同时出现在“查看”菜单 |
| 工作区 | 当前项目/空间可见，切换入口靠近项目名 | 标题栏显示当前工作区；“打开工作区…”统一走文件菜单 |
| 窗口控制 | Windows 自绘三键；macOS 保留红黄绿系统语义 | 统一自绘控件，调用 Tauri 原生窗口 API，浏览器演示模式安全降级 |
| AI 状态 | 模型、连接状态、生成状态需要持续可见 | 标题栏只显示当前模型名；连接状态继续由对话区状态点表达，避免信息拥挤 |
| 菜单密度 | 以少量高频命令为主，低频设置进入二级页面 | 5 个一级菜单，每项控制在 4-5 个命令；不放商城、会员、容量等云产品入口 |
| 平台差异 | 快捷键和窗口行为遵循操作系统习惯 | 菜单展示 `⌘` 语义，Windows 运行时由系统映射为 Ctrl；窗口 API 统一封装 |

这些共性说明了标题栏应当“可发现、可预测、低打扰”：用户能在不离开当前工作区的情况下找到应用级动作，但标题栏本身不应该成为第二个侧边栏。

## 3. 信息架构

```text
标题栏 36px
├── Vinkey / 当前工作区 / 当前模型
├── 文件
│   ├── 新建会话              ⌘/Ctrl + N
│   ├── 打开工作区…           ⌘/Ctrl + O
│   ├── 新建文档…
│   └── 保存文档              ⌘/Ctrl + S
├── 编辑
│   ├── 撤销 / 重做
│   └── 剪切 / 复制 / 粘贴
├── 查看
│   ├── 对话页 / 文件页
│   ├── 切换浅色/深色主题
│   └── 模型与应用设置
├── 窗口
│   ├── 最小化 / 最大化或还原
│   └── 关闭窗口              ⌘/Ctrl + W
├── 帮助
│   ├── 查看快捷键
│   └── 关于 Vinkey
└── 窗口控制：最小化 / 最大化 / 关闭
```

### 3.1 菜单行为规范

- 点击一级菜单打开下拉菜单；点击菜单外、按 Escape 或执行命令后关闭。
- 菜单项左侧使用 Lucide 图标，右侧显示快捷键；文字保持中文，模型名、URL 等用户输入保留原文。
- 下拉菜单宽度固定，命令名称单行省略，避免标题栏因长工作区名跳动。
- 菜单不覆盖窗口控制区域；浮层使用高于编辑器和错误提示的层级。
- 无法执行的操作应禁用或先引导用户（例如没有工作区时，新建文档会先打开工作区）。

### 3.2 窗口与平台

- 标题栏中央空白区标记为 Tauri 拖拽区域；双击标题栏切换最大化。
- 桌面端调用 `minimize`、`toggleMaximize`、`close`；浏览器开发模式不调用窗口 API。
- 关闭窗口不额外弹确认框；未保存状态由编辑器和状态栏持续提示，后续可增加系统级未保存拦截。
- 颜色跟随深色/浅色主题，关闭按钮悬停使用危险色，其他窗口按钮保持中性。

## 4. 快捷键

| 命令 | macOS | Windows / Linux |
| --- | --- | --- |
| 保存文档 | ⌘ S | Ctrl S |
| 新建会话 | ⌘ N | Ctrl N |
| 打开工作区 | ⌘ O | Ctrl O |
| 关闭窗口 | ⌘ W | Ctrl W |
| 撤销 / 重做 | ⌘ Z / ⇧⌘ Z | Ctrl Z / Ctrl Y |
| 发送消息 | Enter | Enter |
| 输入换行 | Shift Enter | Shift Enter |

菜单展示 macOS 语义符号，Windows/Linux 使用时由平台约定映射为 Ctrl；实际编辑器快捷键仍由 CodeMirror 和浏览器事件处理。

## 5. 验收标准

- 首屏标题栏可见，应用名称、工作区状态和窗口控制不被内容区遮挡。
- 五个一级菜单均可打开，核心命令能改变会话、工作区、页面、主题或窗口状态。
- 菜单和按钮在深色、浅色主题下均满足对比度要求；窗口按钮命中区域不小于 44 × 28px。
- 1024px 最小窗口宽度下菜单、工作区信息和窗口控制不发生重叠；工作区名过长时显示省略号。
- 浏览器 `npm run dev` 模式不因 Tauri API 缺失报错；`npm run build` 和 `npm test` 通过。
