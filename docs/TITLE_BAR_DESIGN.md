# Vinkey 系统标题栏与功能菜单设计

- 状态：实现基线
- 日期：2026-08-31
- 适用端：Tauri 2 Windows / macOS 桌面应用

## 1. 目标

标题栏是应用级操作的稳定入口，负责承载窗口管理、当前工作区识别和高频命令。它不重复左侧工具轨或对话工具栏的内容，也不承载营销、账号或云端存储入口。

本次升级包括：

1. 所有应用级菜单统一使用中文。
2. 标题栏菜单可直接执行新建会话、打开工作区、新建文档、保存、页面切换、主题切换和模型设置。
3. Windows 使用自绘标题栏和窗口控制；macOS 恢复原生窗口装饰与红黄绿按钮，菜单进入屏幕顶部系统菜单栏。
4. 菜单显示平台常用快捷键，命令仍由应用状态驱动，避免菜单和工具栏状态不一致。

## 2. 竞品与同类应用观察

本章中的“竞品”采用广义口径，既包括 AI 桌面客户端和写作软件，也包括在跨平台窗口与菜单设计上具有参考价值的成熟工作台。排序衡量的是对 Vinkey 标题栏与功能菜单的参考价值，不代表产品综合能力排名。

### 2.1 排序原则

按以下维度综合排序，优先考虑可沉淀为同类桌面产品通用设计的部分：

| 维度 | 权重 | 判断标准 |
| --- | ---: | --- |
| 使用场景接近度 | 35% | 是否同时涉及本地文档、持续创作、工作区和 AI 辅助 |
| 菜单体系成熟度 | 25% | 文件、编辑、查看、窗口、帮助等应用级命令是否清晰稳定 |
| 平台习惯符合度 | 25% | macOS 是否使用原生菜单栏与窗口装饰，Windows 是否符合窗口控制习惯 |
| 方案可迁移性 | 15% | 是否适合落到 Vinkey 的 Tauri + React 架构，而不依赖云协作或复杂账号体系 |

竞品版本会持续变化；评审时关注稳定的信息架构和平台行为，不复刻某一版本的像素样式。

### 2.2 参考价值排序

| 排名 | 产品 | 产品类型 | 参考价值 | 重点参考内容 | 不直接采用的部分 |
| ---: | --- | --- | --- | --- | --- |
| 1 | Obsidian | 本地优先知识与 Markdown 工作区 | 很高 | 本地仓库识别、文档工作区、跨平台菜单、命令与快捷键的一致性 | 插件市场、知识图谱等与文学创作主流程无关的入口 |
| 2 | Cursor | AI 桌面工作台 | 很高 | AI 与文件工作区并存、当前项目状态、Windows 自绘壳层与 macOS 系统菜单分流 | 面向代码的终端、调试和版本控制菜单 |
| 3 | Typora | 本地 Markdown 写作应用 | 很高 | 低干扰标题栏、原生文件/编辑菜单、保存状态和沉浸式写作体验 | 单文档优先结构，不能覆盖 Vinkey 的多文档工作区与 AI 会话 |
| 4 | Scrivener | 长篇文学创作与项目管理 | 很高 | 长篇创作项目、章节文稿、保存/导出、窗口和文稿命令的层级组织 | 编译出版、复杂元数据等专业功能不进入首版菜单 |
| 5 | Cherry Studio | 本地多模型 AI 客户端 | 高 | 当前模型、会话、模型设置与应用菜单的职责边界；本地模型和多提供商状态 | 多助手、知识库和提供商管理不放入标题栏一级区域 |
| 6 | ChatGPT Desktop | 通用 AI 桌面客户端 | 高 | 新建会话、快捷唤起、设置等少量高频命令；macOS 原生窗口与菜单习惯 | 云账号、语音及全局悬浮入口不是 Vinkey 标题栏的基础能力 |
| 7 | Ulysses | macOS/iOS 写作应用 | 中高 | macOS 原生菜单栏、专注写作、资料库与编辑区的清晰分工 | Apple 单平台交互和订阅同步模型不能直接迁移到 Windows |
| 8 | 豆包桌面端 | 中文通用 AI 客户端 | 中 | 中文菜单命名、聊天高频入口、设置和窗口操作的可发现性 | 消费型内容入口、账号增长入口和云端服务入口 |
| 9 | WorkBuddy | 桌面 AI 助手/工作助手 | 中 | AI 助手在桌面壳层中的快捷入口、任务状态和轻量菜单密度 | 企业协作或助手聚合入口与本地文学创作关联较弱 |
| 10 | Notion Desktop | 云端文档协作工作区 | 较低 | 多文档导航、搜索和工作区切换的稳定位置 | 云空间、成员协作、分享和账号入口不适用于本地优先标题栏 |

#### 排序结论

- **主参考组：Obsidian、Cursor、Typora、Scrivener。** 用于确定本地工作区、创作文件和跨平台菜单的基础骨架。
- **AI 交互参考组：Cherry Studio、ChatGPT Desktop。** 用于确定会话、模型状态和设置入口在标题栏中的信息优先级。
- **平台与中文体验校验组：Ulysses、豆包、WorkBuddy。** 分别校验 macOS 原生习惯、中文命名和桌面 AI 快捷入口，但不作为整体信息架构模板。
- **边界参照组：Notion Desktop。** 只参考成熟的工作区切换和搜索位置，用来提醒设计避免引入云协作产品的账号、分享和容量菜单。

### 2.3 通用设计归纳

综合以上产品，可以归纳出标题栏的通用设计：

| 共性 | 同类市场产品的常见做法 | Vinkey 的取舍 |
| --- | --- | --- |
| 应用身份 | 左侧保留产品名或图标，始终可见 | 使用 V 图标、Vinkey 和当前工作区名；模型名作为弱化状态信息 |
| 快速入口 | 新建会话、搜索、设置等高频操作靠近标题栏或首屏 | 新建会话放入“文件”菜单，搜索保留在左侧工具轨，设置同时出现在“查看”菜单 |
| 工作区 | 当前项目/空间可见，切换入口靠近项目名 | 标题栏显示当前工作区；“打开工作区…”统一走文件菜单 |
| 窗口控制 | Windows 自绘三键；macOS 保留红黄绿系统语义 | Windows 调用 Tauri 窗口 API；macOS 使用原生窗口装饰 |
| AI 状态 | 模型、连接状态、生成状态需要持续可见 | 标题栏只显示当前模型名；连接状态继续由对话区状态点表达，避免信息拥挤 |
| 菜单密度 | 以少量高频命令为主，低频设置进入二级页面 | 5 个一级菜单，每项控制在 4-5 个命令；不放商城、会员、容量等云产品入口 |
| 平台差异 | 快捷键和窗口行为遵循操作系统习惯 | macOS 使用原生全局菜单；Windows 使用 React 菜单，快捷键按平台显示 |

这些共性说明了标题栏应当“可发现、可预测、低打扰”：用户能在不离开当前工作区的情况下找到应用级动作，但标题栏本身不应该成为第二个侧边栏。

## 3. 信息架构

```text
Windows 自绘标题栏 36px；macOS 使用原生窗口标题栏与屏幕顶部菜单栏
├── Vinkey / 当前工作区 / 当前模型（Windows）
├── 文件
│   ├── 新建会话              ⌘/Ctrl + N
│   ├── 打开工作区…           ⌘/Ctrl + O
│   ├── 新建文档…
│   └── 保存文档              ⌘/Ctrl + S
├── 编辑
│   ├── 撤销 / 重做
│   └── 剪切 / 复制 / 粘贴
├── 查看
│   ├── 对话页 / 文件页
│   ├── 切换浅色/深色主题
│   └── 模型与应用设置
├── 窗口
│   ├── 最小化 / 最大化或还原
│   └── 关闭窗口              ⌘/Ctrl + W
├── 帮助
│   ├── 查看快捷键
│   └── 关于 Vinkey
└── 窗口控制：Windows 自绘；macOS 红黄绿原生按钮
```

### 3.1 菜单行为规范

- 点击一级菜单打开下拉菜单；点击菜单外、按 Escape 或执行命令后关闭。
- 菜单项左侧使用 Lucide 图标，右侧显示快捷键；文字保持中文，模型名、URL 等用户输入保留原文。
- 下拉菜单宽度固定，命令名称单行省略，避免标题栏因长工作区名跳动。
- 菜单不覆盖窗口控制区域；浮层使用高于编辑器和错误提示的层级。
- 无法执行的操作应禁用或先引导用户（例如没有工作区时，新建文档会先打开工作区）。

### 3.2 窗口与平台

- Windows 标题栏中央空白区标记为 Tauri 拖拽区域；双击标题栏切换最大化。
- macOS 使用原生窗口装饰和 Tauri 原生菜单 API，菜单自动出现在屏幕顶部；窗口按钮由系统绘制。
- Windows 桌面端调用 `minimize`、`toggleMaximize`、`close`；浏览器开发模式不调用窗口 API。
- 关闭窗口不额外弹确认框；未保存状态由编辑器和状态栏持续提示，后续可增加系统级未保存拦截。
- 颜色跟随深色/浅色主题，关闭按钮悬停使用危险色，其他窗口按钮保持中性。

## 4. 快捷键

| 命令 | macOS | Windows / Linux |
| --- | --- | --- |
| 保存文档 | ⌘ S | Ctrl S |
| 新建会话 | ⌘ N | Ctrl N |
| 打开工作区 | ⌘ O | Ctrl O |
| 关闭窗口 | ⌘ W | Ctrl W |
| 撤销 / 重做 | ⌘ Z / ⇧⌘ Z | Ctrl Z / Ctrl Y |
| 发送消息 | Enter | Enter |
| 输入换行 | Shift Enter | Shift Enter |

菜单展示 macOS 语义符号，Windows/Linux 使用时由平台约定映射为 Ctrl；实际编辑器快捷键仍由 CodeMirror 和浏览器事件处理。

## 5. 验收标准

- Windows 首屏自绘标题栏可见；macOS 使用原生窗口标题栏，应用菜单出现在屏幕顶部。
- 五个一级菜单均可打开，核心命令能改变会话、工作区、页面、主题或窗口状态。
- 菜单和按钮在深色、浅色主题下均满足对比度要求；窗口按钮命中区域不小于 44 × 28px。
- 1024px 最小窗口宽度下菜单、工作区信息和窗口控制不发生重叠；工作区名过长时显示省略号。
- 浏览器 `npm run dev` 模式不因 Tauri API 缺失报错；`npm run build` 和 `npm test` 通过。
