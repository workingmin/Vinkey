# 开源项目竞品分析报告

- 当前数据：[正式名录](COMPETITOR_CATALOG.md)中的开源收录对象为 NoteGen、Cherry Studio，集中维护其采用数据、发行来源与核验边界。
- 观察范围：公开仓库、公开文档和可观察的产品交互；不以代码复制为目的。
- 许可证原则：GPL/AGPL 项目只参考行为和公开架构，具体实现、资源和提示词需独立开发与许可证审查。
- 筛选口径：[竞品筛选方法论](SELECTION_METHODOLOGY.md)。

本报告只分析正式名录中的开源产品：NoteGen、Cherry Studio。未收录的开源项目不再单列分析。

## 1. 项目地图

| 规范名称 | 名录身份 | 主要价值 | 对 Vinkey 的相关度 | 当前结论 |
| --- | --- | --- | --- | --- |
| [NoteGen](https://github.com/codexu/note-gen) | 正式竞品 | Tauri、本地 Markdown、AI 对话与知识内容 | 高 | 已参考本地优先、内容/会话/文档组织；不复制 GPL 代码 |

## 2. 重点功能分析

### 2.1 本地工作区与内容主权

**观察。** NoteGen 和 Cherry Studio 都把本地文件或本地工作区作为核心对象，用户可以理解内容在哪里，界面也围绕当前工作区组织导航。这个模式比“上传文件后等待云端处理”更符合 Vinkey 的创作隐私定位。

**Vinkey 已参考。**

- 以授权工作区、项目和文档作为一级业务对象。
- 读写只经过 Rust 工作区路径守卫，前端不能自行访问任意路径。
- 会话和任务记录放入应用数据目录，文稿仍由用户目录掌控。
- 工作区画像先使用元数据，正文读取由任务策略授权。

**有意不同。** Vinkey 的工作区不是通用知识库。它还要绑定模型连接、会话、分析任务、canon 和项目记忆，因此不会把插件、双向链接或全库索引默认放进核心流程。

**待参考。** 外部文件监听、冲突对比、恢复加载和可解释的“当前项目上下文”提示。验收条件是：编辑器有未保存内容时，外部变化不会静默覆盖；用户能看到差异、选择重新加载或另存为。当前另存为已实现，差异对比 UI 进入验收队列。

### 2.2 提供商、模型与密钥

**观察。** NoteGen 和 Cherry Studio 将服务商连接、模型列表、当前模型和连接测试拆开；这降低了“配置成功但实际调用失败”的误解。

**Vinkey 已参考。**

- Ollama 与 OpenAI-compatible Provider 并列。
- 连接测试和模型发现是设置页的一等状态。
- API Key 只进入系统凭据存储，不进入 SQLite、前端持久化和运行日志。
- 活动模型选择不修改提供商配置。

**不采用。** 首版不追求大量内置云厂商、模型路由市场或跨供应商自动切换。模型切换必须能解释上下文窗口、隐私策略和失败原因。

### 2.3 文档组织与会话记录

**观察。** NoteGen 把本地文档、会话与内容组织在同一工作区；Cherry Studio 把模型会话与工作区状态分层，均强调对象边界清晰，避免把会话记录和用户文件混为同一数据面。

**Vinkey 已参考。**

- 项目、会话、文档和任务分属不同对象，数据按本地工作区隔离。
- 会话和任务记录只删除应用记录，不删除用户目录中的文档。
- 文档保留文件归属、来源和源指纹，不依赖聊天气泡作为唯一数据入口。

**待参考。** 在不引入向量数据库的前提下，评估标题、实体、别名、章节结构和用户确认记忆的混合检索；指标为关键证据召回率、发送正文 token 数和人工纠错时间。当前已有评分/排序原型，真实对比实验待进行。
