# 单个竞品报告模板

复制本文件后，将文件名改为稳定的英文产品名；详细报告放在 `docs/competitors/`，不要把一次体验直接写入架构结论。新报告按[竞品筛选方法论](SELECTION_METHODOLOGY.md)记录统一收录条件、证据角色与验证缺口，并使用[正式竞品名录](COMPETITOR_CATALOG.md)和[竞品术语规范](TERMINOLOGY.md)中的规范名称。竞品图像只允许在会话中观察，不作为仓库资料保存。

## 基本信息

| 字段 | 内容 |
| --- | --- |
| 产品/项目 | `产品名` |
| 类型 | 开源项目 / 商业产品 / Agent Runtime / 编辑器 / 写作工具 |
| 官方入口 | URL |
| 代码仓库 | URL 或“不适用” |
| 许可证/商业条款 | SPDX、官方条款或“待确认” |
| 观察版本/日期 | 版本、套餐、地区、日期 |
| 观察方式 | 源码 / 官方文档 / 实测文字记录 / 会话内截图或演示观察；不将竞品图像入库 |
| 相关 Vinkey 功能 | `CF-*` 编号 |
| 筛选层级 | 正式竞品 / 专项或生态参考 / 观察对象 / 维护复核 / 退出跟踪 |

## 一句话判断

用一段话说明它解决什么问题、对 Vinkey 最有价值的观察是什么，以及它不适合直接迁移的边界。

## 收录与证据核验

| 条件 | 来源角色 / URL / 资料日期 / 端别版本 | 支持的结论与缺口 |
| --- | --- | --- |
| 官方身份与可比产品范围 | O |  |
| 真实采用：独立同类统计或平台/社区使用证据 | M / P / U | 指标、地区、月份、渠道及去重边界 |
| 存续、改名与维护记录 | O / P | 查看近 180 天；存续时间是成熟度线索，不作机械门槛 |
| 具体反馈与修复记录 | O / U | 有反馈入口不等于已核验反馈闭环 |
| 相关创作/文档/任务场景 | O / U；适配判断标 D |  |
| 当前服务状态、许可证/商业边界 | O | 停服/迁移/渠道差异与未核验事项 |

记录身份、当前状态和参考用途，三者不要合成无依据的分数。缺必备证据时进入观察；精确行为未核验时保留缺口，不借同品牌其他产品的证据补齐。

## 已参考功能

逐条写清：

- 采用的用户价值和具体交互。
- Vinkey 对应的业务对象、代码或设计文档。
- 与原产品不同的权限、数据、模型或平台边界。
- 当前测试或验收是否覆盖。

## 待参考功能

每项必须包括：

1. 真实用户场景和不做它的成本。
2. 隐私、许可证、性能和维护风险。
3. 最小可行实现，不引入不必要的 SDK 或平台依赖。
4. 验收指标、测试素材和退出条件。

## 明确不采用

记录被否决的能力、否决日期、原因和可能重新评估的触发条件。常见原因包括：

- 需要新增商用付费 API、账号或云端数据面。
- 与本地正文隐私、离线模型或 Tauri 跨平台边界冲突。
- 会绕过 Proposal、canon、记忆或正式写入审批。
- 展示成本高但没有改善任务完成率、来源准确率或人工修正时间。

## 结论

用不超过五条结论结束报告，并分别标注：进入 Vinkey 的设计文档、实现任务、评测任务或“不再跟进”。
