# 单模型准入与硬件基线

- 状态：当前产品基线
- 日期：2026-09-14
- 适用范围：Ollama 与 OpenAI 兼容模型连接

## 产品约束

Vinkey 只启用一个功能模型。分析、续写、改稿和审校等场景由 Skill 调整提示词、上下文与工作流，不维护轻量模型、综合模型等角色分配，也不允许在对话输入区临时切换模型。

模型连接可以发现多个候选模型，但只有通过准入探测并由用户在设置页选定的模型才会成为活动模型。连接和模型配置保存在本机数据库；唯一活动模型 ID 保存在本地应用存储。

## 准入要求

候选模型必须同时满足：

1. 连接可用，能够从 Ollama `/api/tags` 或 OpenAI 兼容 `/models` 获取目录。
2. 具备中文文本处理能力和业务所需的上下文窗口。
3. 支持严格 JSON Schema 结构化输出，并通过实际请求校验。

模型目录和准入结果会按连接 ID、接口类型与 Base URL 缓存。连接参数变化后缓存失效，用户可以手动刷新目录或重新探测。API Key 不进入浏览器缓存。

## 硬件档位

| 档位 | Apple Silicon 统一内存 | 独立显卡设备（内存 / 单卡显存） |
| --- | --- | --- |
| 最低配置 | 16 GB | 16 GB / 8 GB |
| 标准配置 | 32 GB | 32 GB / 16 GB |
| 推荐配置 | 64 GB | 64 GB / 24 GB |

硬件档位只描述本地运行容量，不自动指定模型。最终能否启用以当前设备和服务上的实际准入探测结果为准。本机 Ollama 默认申请 16,384 tokens 上下文；长文本任务继续使用分块和 Map/Reduce/Synthesis，不要求一次载入整部作品。

## 模型生命周期

准入探测会逐一测试候选模型，并在每个本机 Ollama 模型探测结束后发送 `keep_alive: 0`，避免多个探测模型同时驻留而污染显存测量。

正常业务请求始终使用唯一活动模型。应用不提供“自动释放旧模型”或“停止驻留模型”设置，也不公开模型停止命令；业务模型的驻留周期由 Ollama 或远程服务管理。

## 旧设计清理

旧的模型角色分配、聊天区模型覆盖、自动停止偏好和手动停止命令均不再属于产品合同。启动时会删除历史 `vinkey.modelAssignments` 与 `vinkey.autoStopOllamaModels` 本地配置。
