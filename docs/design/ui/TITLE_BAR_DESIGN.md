## 1. 设计结论

Vinkey 是以项目、会话和本地文档为边界的 AI 创作工作台。全局菜单应先表达用户正在管理的业务对象，再提供平台和窗口命令；不应把单个文档编辑器的菜单骨架直接当成整个应用的骨架。

本轮确定以下目标语义：

1. Windows 和 macOS 的一级业务菜单由“文件”调整为“项目”，并新增独立的“会话”菜单。
2. “项目”负责本地项目/工作区的打开、刷新和后续项目级操作；文档新建、保存、关闭回到文件页工具栏、文档标签和 `Ctrl/Cmd+S` 局部入口。
3. “编辑”采用当前焦点对象语义。对话输入框、文件编辑器、搜索框和设置表单获得焦点时，编辑命令作用于当前可编辑目标；没有目标时禁用命令。它不能被简单解释为“只编辑对话框”。
4. “模型与应用设置”不属于“查看”。Windows 从侧栏设置入口和 `Ctrl/Cmd+,` 进入；macOS 从 `Vinkey` 应用菜单和同一快捷键进入。
5. 用户可见的菜单、菜单项、快捷键说明和无障碍名称使用中文；品牌名、文件格式、协议字段和 API 枚举保留原文。系统注入的 macOS 服务项按平台本地化，不在 Vinkey 自有文案中伪装成中文已覆盖。

当前 `src/App.tsx` 已按本文件迁移菜单树：Windows 使用“项目/会话/编辑/查看/窗口/帮助”，macOS 在同一业务语义前增加 `Vinkey` 应用菜单；设置已移出“查看”，Windows 编辑命令已改为焦点目标与 CodeMirror 命令桥接。此状态只表示源码对齐，不代表 `W0-SHELL-MENU-P/F` 已经通过；仍需 Windows 和 macOS 真实桌面证据。

## 3. 信息架构

本节描述目标信息架构，但菜单项分为“首版核心”和“后续入口”两类。首版核心必须在标题栏专项中验收；后续入口没有实现前不得出现在已实现菜单截图或通过结论中。

```text
macOS 屏幕顶部系统菜单
├── Vinkey
│   ├── 关于 Vinkey
│   ├── 设置…                         ⌘,
│   ├── 服务（系统项）
│   ├── 隐藏 Vinkey / 隐藏其他 / 显示全部
│   └── 退出 Vinkey
├── 项目
│   ├── 添加本地项目…                 ⌘O
│   └── 刷新当前项目                  ⌘R
├── 会话
│   ├── 新建会话                      ⌘N
│   └── 搜索项目与会话                ⌘K（后续入口，CF-023）
├── 编辑
│   ├── 撤销 / 重做
│   ├── 剪切 / 复制 / 粘贴
│   └── 全选
├── 查看
│   ├── 对话工作台
│   ├── 项目文件
│   ├── 任务与日志
│   └── 切换浅色/深色主题
├── 窗口
│   ├── 最小化
│   ├── 缩放窗口
│   ├── 进入全屏
│   └── 关闭窗口                  ⌘W
└── 帮助
    ├── 查看快捷键
    ├── 窗口诊断信息
    └── 应用诊断日志

Windows 自绘标题栏
├── 项目 / 会话 / 编辑 / 查看 / 窗口 / 帮助
└── 最小化 / 最大化或还原 / 关闭窗口
```

以下动作不作为首版全局菜单项：

- “停止当前生成”保留在对话输入区的停止按钮，并由 `Esc` 作为快捷路径；全局菜单项会抢占输入焦点、增加运行态菜单状态同步，不纳入当前标题栏目标。
- “展开/折叠项目与会话栏”保留在侧栏按钮；它是壳层布局控制，不重复放入“查看”。
- `⌘/Ctrl+K` 全局搜索只有在 `CF-023` 完成后加入“会话”菜单。当前侧栏搜索不能冒充该菜单能力。

Windows 不显示 macOS 的 `Vinkey` 应用菜单；“关于 Vinkey”放在“帮助”末项。macOS 的“关于 Vinkey”和系统服务由应用菜单承载，不在“帮助”重复。

## 4. 菜单逐项规范

### 4.1 项目

| 菜单项 | 快捷键 | 前置条件 | 行为 | 证据/决策 | 不放入此处 |
| --- | --- | --- | --- | --- | --- |
| 添加本地项目… | `Cmd/Ctrl+O` | 无 | 选择本地目录，登记为项目并进入工作台；失败保留原项目 | `TB-EV-001`、`TB-EV-003` → `TB-DEC-001` | 新建文档、打开单个文件 |
| 刷新当前项目 | `Cmd/Ctrl+R` | 已打开项目 | 更新项目、会话摘要和文件树；不清除当前会话或编辑草稿 | `TB-EV-001`、`TB-EV-003` → `TB-DEC-001` | 删除项目记录；危险操作留在项目上下文菜单 |

“项目”是面向用户的一级对象名称；代码和数据层可以继续使用 `workspace` 表示本地目录权限边界。项目切换、删除记录和项目内文件树的详细规则由 [UI_DESIGN_NAVIGATION.md](./UI_DESIGN_NAVIGATION.md) 负责。

### 4.2 会话

| 菜单项 | 快捷键 | 前置条件 | 行为 | 证据/决策 | 状态 |
| --- | --- | --- | --- | --- | --- |
| 新建会话 | `Cmd/Ctrl+N` | 无；无项目时先提示添加项目 | 创建当前项目下的空白会话并进入对话页 | `TB-EV-001`、`TB-EV-002` → `TB-DEC-001` | 已有实现，菜单迁移待完成 |
| 搜索项目与会话 | `Cmd/Ctrl+K` | 应用已启动 | 打开统一搜索面板，按项目、会话、当前项目文档分组；`Escape` 返回原页面 | `TB-EV-001`、`TB-EV-004` → `TB-DEC-001`；`CF-023` | 待实现 |
| 局部动作：停止当前生成 | `Esc` | 当前会话正在生成 | 通过对话输入区停止按钮请求进入停止状态；保留已经产生的内容和活动记录 | `TB-EV-002`、`TB-EV-006` → `TB-DEC-003` | 不属于首版全局菜单项；由 `D-CHAT` 验收 |

会话重命名、删除和标题生命周期属于会话行或上下文菜单，不放入全局菜单，以降低危险操作误触和菜单密度。详见 [UI_DESIGN_NAVIGATION.md](./UI_DESIGN_NAVIGATION.md) 与 `CF-022`。

### 4.3 编辑

编辑菜单只提供平台通用的编辑命令，接收者由焦点和当前页面状态决定：

| 命令 | 对话输入框 | 文件编辑器 | 搜索/设置输入框 | 无有效目标 | 证据/决策 |
| --- | --- | --- | --- | --- | --- |
| 撤销 / 重做 | 输入历史 | 文档变更历史 | 表单/搜索变更历史 | 禁用 | `TB-EV-004`、`TB-EV-006` → `TB-DEC-003` |
| 剪切 / 复制 / 粘贴 | 当前选中文本 | 当前选中文本 | 当前选中文本 | 禁用 | `TB-EV-004`、`TB-EV-006` → `TB-DEC-003` |
| 全选 | 当前输入或消息可选区 | 当前文档/编辑器 | 当前字段 | 禁用 | `TB-EV-004`、`TB-EV-006` → `TB-DEC-003` |

命令执行必须通过明确的输入控件或 CodeMirror 命令桥接，并保持焦点、选区和页面不变。Windows 不得继续对任意页面调用 `document.execCommand`；macOS 的原生预定义编辑项也必须验证当前 WebView 焦点确实能够接收命令。

### 4.4 查看

“查看”只切换内容承载或视觉状态，不执行项目写入、会话删除、模型配置等业务操作：

| 菜单项 | 行为 | 证据/决策 |
| --- | --- | --- |
| 对话工作台 | 切换到 `chat` 内容页，保留当前会话和生成状态 | `TB-EV-001`、`TB-EV-002` → `TB-DEC-001` |
| 项目文件 | 切换到 `file` 内容页，保留当前会话和编辑草稿 | `TB-EV-003`、`TB-EV-005` → `TB-DEC-002` |
| 任务与日志 | 切换到 `logs` 内容页，不改变当前会话 | `TB-EV-001`、`TB-EV-004` → `TB-DEC-001` |
| 侧栏按钮：展开/折叠项目与会话栏 | 从侧栏按钮改变壳层宽度，不清除选择和生成状态；不在“查看”菜单呈现 | `TB-EV-001`、`TB-EV-004` → `TB-DEC-006` |
| 切换浅色/深色主题 | 只改变主题，不改变项目、会话和编辑状态 | `TB-EV-004`、`TB-EV-006` → `TB-DEC-006` |
| 模型与应用设置 | 从本菜单移除；设置页由侧栏或平台应用菜单进入 | `TB-EV-002`、`TB-EV-004` → `TB-DEC-004` |

### 4.5 窗口

窗口菜单保留操作系统级动作：

| 菜单项 | 行为 | 证据/决策 |
| --- | --- | --- |
| 最小化 | 最小化当前应用窗口 | `TB-DEC-006` |
| 最大化/还原 | 在最大化和上一个窗口尺寸之间切换 | `TB-DEC-006` |
| 进入全屏（macOS） | 按平台进入或退出全屏 | `TB-DEC-006` |
| 关闭窗口 | 关闭应用窗口；未保存文档由编辑器和平台关闭流程拦截 | `TB-EV-004`、`TB-DEC-006` |

“关闭窗口”不把“关闭文档”混入其中。

### 4.6 帮助与诊断

帮助菜单提供以下入口：

| 菜单项 | 行为 | 证据/决策 |
| --- | --- | --- |
| 查看快捷键 | 打开当前平台和焦点规则的快捷键说明 | `TB-EV-004`、`TB-EV-006` → `TB-DEC-003` |
| 窗口诊断信息 | 打开只读、可复制、脱敏的窗口和平台信息 | `TB-DEC-006` |
| 应用诊断日志 | 查看应用事件，不改变会话或项目状态 | `TB-EV-004` → `TB-DEC-006` |
| 关于 Vinkey（Windows） | 查看应用版本和构建信息 | `TB-DEC-005`、`TB-DEC-006` |

macOS 的“关于 Vinkey”放在 `Vinkey` 应用菜单，不在“帮助”重复。诊断内容不得显示 API Key、完整正文、系统用户名或未脱敏绝对路径。

## 5. 平台、语言和焦点规则

### 5.1 平台承载

| 能力 | Windows | macOS | 共同语义 |
| --- | --- | --- | --- |
| 一级菜单 | 自绘标题栏内的项目/会话/编辑/查看/窗口/帮助 | 屏幕顶部系统菜单 | 菜单项职责、前置条件和快捷键一致 |
| 应用菜单 | 无独立产品应用菜单；关于放帮助 | `Vinkey` 应用菜单 | 设置和关于不属于查看 |
| 窗口控制 | 自绘最小化、最大化/还原、关闭 | 原生红黄绿交通灯 | 状态同步，命中区域符合平台规范 |
| 菜单关闭 | 外部点击、`Escape`、执行命令 | 系统菜单行为；命令后返回 WebView 焦点 | 关闭后焦点回到触发入口或目标内容 |

### 5.2 中文替换审计

| 审计对象 | 目标用户可见文字 | 处理 |
| --- | --- | --- |
| 一级菜单 | 项目、会话、编辑、查看、窗口、帮助 | 统一中文；不再出现 `File`、`View`、`Settings` 等自有菜单标签 |
| 编辑命令 | 撤销、重做、剪切、复制、粘贴、全选 | 由平台行为执行，显示文字由 Vinkey 或系统本地化提供 |
| 技术字段 | Vinkey、Ollama、OpenAI、Markdown、TXT、UTF-8、Base URL、API Key | 品牌、格式和协议字段保留原文 |
| 内部 API 标识 | `Undo`、`CloseWindow`、`CmdOrCtrl+S` | 只作为代码枚举/快捷键，不直接写入自有用户文案 |
| 系统注入项 | macOS 服务、隐藏、显示全部等 | 由操作系统本地化，不把系统项误报为 Vinkey 自有菜单已覆盖 |

新增或改名菜单时，必须同时更新 Windows 自绘菜单、macOS 原生菜单、`UI_ENTRY_POINTS.md`、本表和自动化验收选择器。

### 8.2 审计结论

1. 当前源码已实现目标菜单树、平台设置归属、快捷键和 Windows 焦点桥接；当前版本仍不能在缺少桌面专项证据时签署目标菜单通过。
2. “停止当前生成”和“查看 > 展开/折叠项目与会话栏”属于重复或高状态同步成本入口，降级为对话/侧栏入口，不作为首版全局菜单项。
3. 全局搜索仍是独立实现缺口；设置快捷键、macOS `Vinkey > 设置…`、Windows 编辑焦点分派和项目/会话菜单迁移已进入待验收状态。
4. `window.alert` 能证明动作被触发，不能证明最终视觉、无障碍和焦点质量；帮助菜单验收必须区分“动作可触发”和“交互完成”。

标题栏专项只有在 Windows/macOS 两个平台的核心菜单命令均有真实桌面证据、编辑焦点和中文审计通过后，才能把 `W0-SHELL-MENU-P/F` 标记为通过。壳层脚本在截图前只执行菜单合同守卫，不执行菜单命令，也不代替上述专项结论。`CF-023` 是会话搜索的独立阻断项，不得为了标题栏结构验收而伪造通过。
