## 核心定义

日志中心的一级列表对象是**请求执行记录**。一条日志行表示一次用户请求或一次由请求触发的服务执行，回答以下问题：请求是什么、当前或最终状态是什么、公开执行过程走到哪里、结果是什么、失败原因是什么，以及如何回到发起请求的对话消息。

日志行不是 Agent 流程节点，也不是后台 `TaskJob` 对象的列表。`TaskJob`、Step、Event 和 checkpoint 只是长文本请求的后台执行遥测，用于补充同一条请求执行记录的详情。它们不能在页面语义上替代请求本身。

请求执行记录的稳定关联优先级如下：

1. `sourceMessageId`：请求在对话中的用户消息 ID，是返回来源和去重的主关联。
2. `requestId`：当前内存运行的请求 ID，用于监控尚未完成的请求。
3. `taskId`：当历史长文本请求只有后台持久化信息时，作为执行记录的技术标识，不代表新增的业务对象。

## 目标与边界

日志中心是当前工作区请求执行的只读可观测页面，用于总览状态、公开运行过程、结果摘要和失败原因，并能回到来源对话的具体消息。它不展示隐藏思维链，也不提供通用 IDE 的构建、终端或插件日志。

页面合并三类请求执行来源：

| 来源 | 持久化/实时依据 | 在日志中心中的含义 |
| --- | --- | --- |
| 已完成普通请求 | 助手消息的 `activityLog`、`runResult` | 一次已保存的对话请求执行记录 |
| 当前请求 | 内存 `chatRuns` | 一次仍在执行中的请求执行记录 |
| 长文本请求 | `TaskJob/Step/Event/Failure` 及其来源消息 | 同一请求的增强执行记录，补充步骤、检查点、产物和指标 |

同一长文本请求同时存在对话消息和后台遥测时，以 `sourceMessageId` 合并为一条日志行，不重复展示。没有对话来源的旧后台记录可以作为“无来源执行记录”展示，但仍只表示一次服务执行，不应命名为独立任务。

日志中心不修改请求输入、对话正文或源文档。暂停、继续、取消和失败重试属于来源对话的请求控制，不属于日志中心的一级操作。

## 页面入口与信息归属

- 内容区顶栏的“日志”标签与“对话”“文件”互斥；标题栏“查看”菜单提供“日志中心”命令。
- 无工作区时显示“未打开项目”空态，不请求执行记录。
- 项目表示日志查询范围。当前页面只读取当前项目，最多加载最近 50 个对话的持久化请求记录，并轮询当前工作区的后台执行遥测。
- 当前活动模型不代表历史请求实际使用的模型；历史模型和服务名称必须使用执行时快照。
- 对话是请求来源，不是日志行本身；有 `sourceMessageId` 时，“打开对话”直接定位到发起消息。
- 跨项目汇总属于目标态。后端支持全局请求执行索引后，顶部增加“全部项目/当前项目”范围选择。

## 执行记录行

- 列表使用“执行记录 / 状态 / 更新时间 / 来源对话”四列；所有记录复用相同列宽。
- 每一行对应一次请求执行。主列第一行显示请求摘要，第二行显示“对话请求”或“后台增强执行”及来源对话。
- 长文本请求对应的 `TaskJob` 不新增一行；它只为同一请求提供更完整的执行详情。
- 点击记录主按钮展开或收起详情；展开按钮使用 `aria-expanded`。
- 来源列只提供返回来源对话入口。列表行不设置独立的查看结果、显示错误或逐条删除按钮。
- 逐条删除暂不提供：请求日志、会话消息、后台遥测和分析产物具有不同生命周期，删除前必须明确范围与恢复策略。

## 工具栏与清理边界

- 左侧按 `running + paused` 统计“运行”，分别统计“完成”和“失败”。
- 右侧按“清理已结束请求记录 / 刷新”排列；刷新保持最右侧。
- “清理已结束请求记录”清理当前日志中心显示的 `completed`、`failed`、`cancelled` 请求记录：清除对话助手消息上的运行元数据，并清理对应的后台执行遥测文件。
- `planned`、`running`、`paused` 请求不清理；用户对话正文和分析产物也不删除。它不是删除会话或逐条删除消息的功能。
- 清理前必须二次确认；清理期间工具栏按钮禁用，完成后刷新列表并保留仍在执行的请求。
- 刷新期间列表保留原内容，避免跳变。

## 请求摘要与执行详情

- 主标题使用请求动作和对象生成确定性摘要，例如“分析《第三卷》人物关系”“汇总全项目故事线”。
- 次标题使用“对话请求 · 会话摘要”；无来源时使用“无来源执行记录”。
- 完整请求摘要、项目名、会话名、请求 ID、来源消息 ID和创建时间进入 tooltip 或展开详情。
- 失败请求优先显示错误代码、用户可读消息和“可重试/需重新发起”语义。
- 普通请求显示 `activityLog`；长文本请求在同一详情中显示后台公开阶段、步骤状态、执行次数和检查点。
- 详情显示请求执行时的模型名和服务名快照；公开事件按时间显示事件语义，不展示隐藏思维链、请求正文或敏感字段。
- 完成的长文本请求按需读取只读分析产物，显示模型调用次数、缓存命中、耗时、产物目录和结果正文。

## 请求执行状态

| 状态 | 用户文案 | 含义 |
| --- | --- | --- |
| `planned` | 等待中 | 后台执行已规划，尚未开始公开阶段 |
| `running` | 运行中 | 请求仍在执行 |
| `paused` | 已暂停 | 请求的后台执行被暂停 |
| `completed` | 已完成 | 请求得到完成结果 |
| `failed` | 失败 | 请求执行失败，详情包含结构化原因 |
| `cancelled` | 已取消 | 请求被用户停止或取消 |

顶层状态描述请求执行结果；后台步骤状态只用于展开详情，不构成另一组顶层日志行，也不覆盖请求级失败原因。

## 与消息活动轨迹的边界

- 消息活动轨迹位于对话消息内部，回答“这次请求正在做什么”。
- 日志中心回答“当前项目的请求执行过什么、运行到哪里、哪里失败、结果在哪里”。
- 来源对话回答“如何暂停、继续、取消或重试这次请求”。
- 普通请求以助手消息的 `runResult/activityLog` 为持久化依据；长文本请求以同一请求关联的后台执行遥测补充详情。
- 对话消息和后台遥测关联同一个请求时，以 `sourceMessageId` 去重，只保留一条信息更完整的请求执行记录。
- 日志中心只显示公开阶段、结果摘要、失败原因和产物，不重复渲染完整回答、隐藏思维链或逐 token 输出。

## 核心流程

### 查看请求执行记录

1. 用户进入“日志”页。
2. 页面按请求关联键合并最近对话、当前请求和后台执行遥测，并按 `updatedAt` 倒序排列。
3. 用户按全部、运行、失败、完成筛选，或搜索对话、请求和错误。
4. 用户展开记录查看公开执行过程、失败原因、结果摘要、后台步骤和产物。
5. 用户点击刷新时保留当前筛选；工作区切换后清理失效详情。

### 返回请求来源

1. 有 `conversationId` 的记录显示“打开对话”入口；旧记录缺少来源字段时不伪造入口。
2. 入口加载当前项目对话、切换到对话页，并用 `sourceMessageId` 定位发起请求的消息。
3. 请求的暂停、继续、取消和失败重试在来源对话中完成，日志中心只提供定位。

### 查看结果与诊断

1. 列表行不显示独立“查看结果”按钮；用户点击请求摘要展开统一详情。
2. 展开已完成的长文本请求时按需读取分析产物，并显示稳定加载状态。
3. 用户查看详情后，可从详情末尾复制结构化诊断摘要；摘要包含请求记录 ID、状态、快照、失败信息和公开事件。
4. 诊断摘要不得包含 API Key、请求正文、源文件指纹或隐藏思维链。

## 响应式、隐私与数据边界

- 桌面宽度使用执行记录、状态、时间、来源四列；窄屏改为两列，时间隐藏，来源入口移到下一行。
- 执行详情和结果正文允许纵向滚动；长 ID、错误消息、路径和结果文本自动换行。
- 所有图标按钮提供可读 `title` 和 `aria-label`；状态使用文字而不是仅改变颜色。
- 日志行只显示当前工作区请求执行记录；请求输入哈希、源文件指纹和内部事件不直接作为 UI 主文案。
- 结果正文和产物路径可能包含用户创作内容，日志中心不写入浏览器历史或应用诊断日志。
- API Key、模型凭据和隐藏思维链不进入请求列表、执行详情或结果指标。

## 请求记录展示元数据

以下字段用于稳定展示和回溯请求执行，不表示新增的“任务”一级对象：

| 字段 | 用途 | 展示规则 |
| --- | --- | --- |
| `displayTitle` | 稳定、可读的请求摘要 | 主标题；本地确定性生成 |
| `conversationId` / `sourceMessageId` | 返回请求来源 | 用于跳转和去重，不直接作为主文案 |
| `workspaceNameSnapshot` | 请求执行时项目名称 | 详情展示；项目重命名后仍可追溯 |
| `conversationTitleSnapshot` | 请求执行时会话名称 | 次标题；会话改名不覆盖历史快照 |
| `modelNameSnapshot` / `connectionNameSnapshot` | 实际执行模型和服务 | 详情展示；配置删除后仍保留历史语义 |
| `taskId` | 后台执行遥测技术标识 | 详情和诊断中展示，不作为请求标题 |

## 验收标准

1. 从内容区“日志”标签和标题栏菜单均可进入日志中心，且不改变当前对话或工作区。
2. 顶部明确显示当前项目范围；当前活动模型不能被误认为历史请求使用的模型。
3. 每一行对应一次请求执行；同一长文本请求的对话消息和后台执行遥测不得重复展示。
4. 支持按全部、运行、失败、完成筛选，并可按对话、请求或错误搜索。
5. 列表具有可见的“执行记录 / 状态 / 更新时间 / 来源对话”表头；桌面宽度下所有记录严格对齐相同列宽。
6. 展开记录后能看到来源、实际模型快照、失败原因、公开执行阶段、后台步骤、执行次数、检查点和公开事件时间线。
7. 日志中心不提供暂停、继续、取消、重跑和修改请求输入控件；这些操作在来源对话完成。
8. 展开完成的长文本请求时按需读取只读结果、产物目录、模型调用次数、缓存命中和耗时；读取失败在详情内可重新加载。
9. “清理已结束请求记录”只清理当前日志中心显示的已结束请求运行元数据和后台遥测；运行中的请求、对话正文和分析产物保留。
10. 1440×900、1280×800、1024×680 以及窄屏下无文字、面板和按钮重叠；键盘焦点和减少动态效果符合系统设计标准。
11. 日志中心不显示 API Key、隐藏思维链或未授权正文，不直接修改源文档。
12. 返回来源对话后定位到发起消息；无来源的旧执行记录不伪造跳转入口。
13. 表中每个 `UI-*` 均关联有效的 `BF-*`、`EP-*`，实现状态与源码和目标态缺口一致。

## 目标态缺口

- 全局请求执行索引、“全部项目/当前项目”范围选择和跨项目并发状态刷新。
- 统一的 RequestExecutionEvent/JobService 状态源和跨会话请求通知。
- 请求执行事件的分页、筛选和更完整的链路耗时聚合。
- 首次加载骨架屏、局部错误重试和结果预览内联错误，而不是依赖全局错误条。
- 超过最近 50 个对话后的增量加载、时间范围筛选和日志归档策略。
- 请求日志与后台遥测的独立保留周期和可恢复归档策略。
