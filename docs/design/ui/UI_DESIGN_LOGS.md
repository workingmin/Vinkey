# UI 设计：日志中心

- 状态：当前实现基线，对话与后台任务统一可观测
- 日期：2026-09-17
- 适用端：Windows、macOS 桌面应用；浏览器模式仅提供有限演示能力
- 关联文档：[UI_INVENTORY.md](./UI_INVENTORY.md)、[UI_DESIGN_CHAT.md](./UI_DESIGN_CHAT.md)、[UI_DESIGN_STATES.md](./UI_DESIGN_STATES.md)、[TEMPORARY_INTERACTION_STATES.md](./TEMPORARY_INTERACTION_STATES.md)

## 目标与边界

日志中心是当前工作区对话运行和后台任务的只读可观测性页面，用于总览每次请求的状态、公开运行过程、结果摘要和失败原因，并能回到来源对话的具体消息。它不展示隐藏思维链，也不提供通用 IDE 的构建、终端或插件日志。

页面合并三类运行记录：

- 普通对话：来自已保存助手消息的 `activityLog` 和 `runResult`，显示处理阶段、结果摘要和结构化失败。
- 当前运行：来自内存中的 `chatRuns`，用于监控尚未完成的对话请求。
- 后台任务：来自持久化 `TaskJob/Step/Event/Failure`，继续提供检查点、分析产物和运行指标。

同一长文本请求只显示一条后台任务记录，不再重复显示对应的对话运行记录。日志中心不改变任务状态、不编辑源文档、不修改请求输入；暂停、继续、取消和失败重试统一由来源对话承担。

## 页面入口

- 内容区顶栏的“日志”标签与“对话”“文件”互斥。
- 标题栏“查看”菜单提供“日志中心”命令；命令只切换内容页，不改变当前会话。
- 无工作区时仍可进入页面，但显示“未打开项目”空态，不请求运行记录。
- 设置页打开时日志中心不可见；任务执行期间设置页会锁定模型和连接修改。

## 信息归属

- 项目表示日志查询范围。当前日志中心只读取当前项目，最多加载最近 50 个对话的持久化运行记录，并持续轮询后台任务状态。
- 当前活动模型不代表历史任务实际使用的模型。日志中心顶部不把“当前项目 · 当前模型”作为任务归属；如应用壳层必须保留活动模型，应明确标注为“新任务默认模型”。
- 任务实际使用的模型属于执行快照，在任务展开详情中显示模型名和服务名；切换活动模型不能改变已有任务的记录。
- 对话表示运行来源，放在运行标题的次级信息中；有来源消息 ID 时，“打开对话”直接定位到该消息。无对话来源的后台任务显示“独立运行”。
- 跨项目汇总属于目标态。后端支持全局任务索引后，顶部增加“全部项目/当前项目”范围选择；只有“全部项目”范围下才在任务行显示项目短名。

### 工具栏

- 工具栏保持稳定高度；左侧按“运行”统计 `running + paused`，分别统计“完成”和“失败”。
- 右侧按“清理后台任务记录 / 刷新”排列；刷新保持最右侧，清理作为有副作用的操作放在刷新左侧。
- “清理后台任务记录”仅清理当前项目中 `completed`、`failed`、`cancelled` 的后台任务状态记录；`planned`、`running`、`paused` 任务不会被清除，对话执行日志和分析产物也不会删除。
- 清理前必须二次确认；清理期间两个工具栏按钮禁用，完成后刷新列表并保留仍在运行的任务。
- 刷新期间按钮禁用并显示旋转图标，列表保留原内容，避免跳变。
- 统计只针对当前工作区，由已保存对话、当前 `chatRuns` 和 `listTaskJobs()` 结果合并后计算。
- 项目范围位于页面顶部，不与统计混排；当前实现阶段仅展示当前项目，不提供无效的跨项目选择器。

### 运行记录行

- 列表提供可见表头，并严格使用“执行记录 / 状态 / 更新时间 / 来源对话”四列；所有记录复用相同列宽。
- 默认每条记录折叠。主列第一行显示请求或后台任务摘要，第二行显示“对话运行/后台任务”类型和来源对话。
- 点击记录主按钮展开/收起详情；当前实现保持单个展开。
- 展开按钮使用 `aria-expanded`；项目名、会话名和任务摘要通过独立字段截断，tooltip 展示完整值，不能拼成长字符串后整体截断。
- 来源列只提供返回来源会话入口。任务标题统一负责展开详情；列表行不设置“查看结果”“显示错误”或逐条删除等重复/高风险入口。
- 逐条删除暂不提供：对话日志与会话消息、后台任务状态和分析产物存在不同生命周期，逐条删除必须先明确删除范围与恢复策略；当前仅提供范围明确的“清理后台任务记录”。
- 页面不得调用暂停、恢复、取消或重跑接口，不提供步骤选择器。任务状态变更统一在来源会话内完成。

### 任务标题与来源

- 不使用“项目名 · 会话名 · 任务名”的单行三段式标题，避免长项目名和会话名挤掉任务含义。
- 主标题使用任务动作和对象生成确定性摘要，例如“分析《第三卷》人物关系”“汇总全项目故事线”，建议控制在 16–24 个中文字符。
- 次标题使用“会话：会话摘要 · #短编号”；无会话来源时使用“独立任务 · #短编号”。短编号只用于消歧，不能代替可读任务摘要。
- 当前项目范围下不在每行重复项目名；未来“全部项目”范围下，在主标题前增加项目短名标签。
- 完整项目名、会话名、任务 ID、来源消息和创建时间进入 tooltip 或展开详情。
- 任务摘要在创建时生成并持久化。首版采用本地确定性规则，不依赖额外模型调用；会话后续改名不覆盖任务创建时的来源快照。

### 任务详情

- 失败任务优先显示错误代码、用户可读错误消息和“可重试/需重新发起”语义。
- 步骤使用中文短标签：文档分块、逐块分析、章节汇总、卷级汇总、最终综合、证据校验和分层归并。
- 每步显示状态、执行次数和检查点；状态不能只依赖颜色，应同时使用文字、图标或位置。
- 详情显示任务创建时的模型名和服务名快照；模型后来切换、重命名或删除时，历史任务仍保留原执行信息。
- 详情按时间显示公开业务事件，至少包含时间、事件语义和关联步骤；不展示隐藏思维链、请求正文或事件中的敏感字段。
- 复制诊断摘要位于展开详情末尾，仅在用户查看上下文后提供；列表行不常驻复制入口。
- 展开已完成任务时自动按需读取产物，并显示模型调用次数、跨任务缓存命中、任务内检查点命中、耗时、产物目录和结果正文；已读取产物在当前页面生命周期内复用。
- 产物读取失败在详情内保留错误原因和“重新加载”入口，不使用全局错误反馈替代局部状态。
- 产物正文保持只读，长内容在固定区域滚动，不把结果直接写回源文档。

## 状态语义

### 任务状态

| 稳定状态 | 用户文案 | 表现 | 当前实现 |
| --- | --- | --- | --- |
| `planned` | 等待中 | 中性文字，允许展开查看已规划步骤 | 已实现 |
| `running` | 运行中 | 强调色文字，步骤中显示当前执行项 | 已实现 |
| `paused` | 已暂停 | 警示色文字，计入运行统计 | 已实现（展示） |
| `completed` | 已完成 | 成功色文字，展开时按需读取产物 | 已实现 |
| `failed` | 失败 | 错误色文字，显示失败原因和来源会话入口 | 已实现 |
| `cancelled` | 已取消 | 中性终止状态，不读取分析产物 | 已实现（展示） |

### 步骤状态

`pending`、`running`、`completed`、`failed`、`cancelled` 只描述当前步骤，不覆盖任务级失败原因。步骤状态、执行次数和检查点来自持久化 `TaskJob`，前端不根据等待时间猜测状态。

### 与消息活动轨迹的边界

- 消息活动轨迹位于对话消息内部，回答“这次请求正在做什么”。
- 日志中心回答“当前项目的各对话运行过什么、运行到哪里、哪里失败、结果在哪里”。
- 来源会话回答“如何暂停、继续、取消或重试这次任务”。
- 普通对话以助手消息的 `runResult/activityLog` 为持久化依据；后台任务以 `TaskJob` 为依据。
- 两者关联同一个长文本请求时，以 `sourceMessageId` 去重，只保留信息更完整的后台任务记录。
- 日志中心只显示公开阶段、结果摘要、失败原因和产物，不重复渲染完整回答、隐藏思维链或逐 token 输出。

## 核心流程

### 查看运行记录

1. 用户进入“日志”页。
2. 页面合并最近对话、当前运行和后台任务，并按 `updatedAt` 倒序排列。
3. 用户按全部、运行、失败、完成筛选，或搜索对话、请求和错误。
4. 用户展开记录查看运行过程、失败原因、结果摘要、步骤和产物。
5. 用户点击刷新时保留当前筛选；工作区切换后清理失效详情。

### 返回来源处理

1. 有 `conversationId` 的记录显示“打开来源对话”入口；旧任务缺少来源字段时不伪造入口。
2. 入口加载当前项目对话、切换到对话页，并用 `sourceMessageId` 定位发起请求的消息。
3. 来源会话按持久化 `TaskJob` 显示运行、暂停或失败任务的控制区。
4. 运行中任务可暂停或取消，暂停任务可继续或取消，可重试失败可选择检查点后重试。
5. 不可重试失败保留原因，但不能提交重试。

控制命令仍由后端保证状态转换、幂等与检查点有效性；日志中心只负责定位和导航。

### 查看业务链路与复制诊断

1. 展开任务后按时间显示最近 50 条公开任务事件。
2. 事件显示用户可理解的语义，并保留步骤名称用于定位链路阶段。
3. 用户查看详情后，可从详情末尾复制结构化诊断摘要；列表行不提供重复的复制按钮。
4. 复制诊断包含任务 ID、状态、项目/会话/模型快照、失败信息和公开事件。
5. 诊断摘要不得包含 API Key、请求正文、源文件指纹或隐藏思维链。

### 展开完成任务

1. 列表行不显示独立“查看结果”按钮；用户点击任务标题展开统一详情。
2. 展开已完成任务时调用 `getLongTextWorkerOutput(jobId)`，并在详情内显示稳定加载状态。
3. 结果显示只读正文、产物目录和运行指标；读取失败在详情内显示原因和“重新加载”。
4. 结果已加载时折叠后再次展开直接使用当前页面缓存，不重复请求。
5. 已展开任务在轮询中转为完成时自动读取产物，无需用户先折叠再展开。

## 响应式与无障碍

- 桌面宽度任务行采用任务、状态、时间、来源四列；内容区最小宽度不足时任务行改为两列，时间隐藏，来源入口移到下一行。
- 任务详情和结果正文允许纵向滚动；长 task ID、错误消息、路径和结果文本自动换行。
- 所有图标按钮必须有可读 `title` 和 `aria-label`；展开按钮提供 `aria-expanded`。
- 刷新和结果读取期间避免重复请求；状态变化应使用状态文本而不是仅改变颜色。来源会话的控制命令提交期间按钮禁用。
- 深浅主题、键盘焦点、中文 IME 和 `prefers-reduced-motion` 按系统级验收标准复验。

## 数据与隐私边界

- 任务列表只显示当前工作区任务；任务输入哈希、源文件指纹和内部事件不直接作为 UI 主文案。
- 结果正文和产物路径可能包含用户创作内容，日志中心不写入浏览器历史或日志。
- 产物预览为只读，不允许在日志中心直接覆盖源文件。
- API Key、模型凭据和隐藏思维链不进入任务列表、步骤详情或结果指标。

### 任务展示元数据（目标态）

当前 `TaskJob` 只有 `workspaceId`、`taskType` 和 `instructionHash` 等执行字段，不能可靠生成任务摘要、会话来源和实际模型。目标态在任务创建时增加以下持久化字段；旧任务缺少字段时使用任务类型、完整 task ID 和“来源未知”降级展示。

| 字段 | 用途 | 展示规则 |
| --- | --- | --- |
| `displayTitle` | 稳定、可读的任务摘要 | 主标题；本地确定性生成，可由后续功能显式重命名 |
| `conversationId` / `sourceMessageId` | 返回任务来源 | 不直接作为主文案；用于跳转和消歧 |
| `workspaceNameSnapshot` | 创建时项目名称 | 全部项目范围或详情展示；项目重命名后仍可追溯 |
| `conversationTitleSnapshot` | 创建时会话名称 | 次标题；后续会话改名不覆盖快照 |
| `modelProfileId` | 执行模型引用 | 用于内部关联，不单独作为历史显示依据 |
| `modelNameSnapshot` / `connectionNameSnapshot` | 实际模型和服务 | 展开详情展示；模型配置删除后仍保留历史语义 |

模型字段只保存名称和服务显示快照，不保存 API Key、请求正文或连接凭据。新增字段应提供序列化默认值，保证已有 `task.json` 可以继续读取。

## 验收标准

1. 从内容区“日志”标签和标题栏菜单均可进入日志中心，且不改变当前对话或工作区。
2. 顶部明确显示当前项目范围；当前活动模型不能被误认为历史运行使用的模型。
3. 普通对话、当前运行和后台任务进入同一列表；同一长文本请求不得重复展示。
4. 支持按全部、运行、失败、完成筛选，并可按对话、请求或错误搜索。
5. 列表具有可见的“执行记录 / 状态 / 更新时间 / 来源对话”表头；桌面宽度下所有记录严格对齐相同列宽。
6. 日志中心不存在暂停、继续、取消、重跑和任务输入修改控件；来源列只提供返回来源会话，列表行不提供独立“查看结果”或“显示错误”按钮，复制诊断摘要位于展开详情末尾。
7. 展开任务后能看到来源、实际模型快照、失败原因、步骤状态、执行次数、检查点和公开事件时间线；模型切换不能改变已有任务的执行信息。
8. 展开完成任务时自动读取只读结果、产物目录、模型调用次数、缓存命中和耗时；读取失败在详情内可重新加载且不清除任务状态。
9. 任务列表只显示所选范围的数据，定时刷新不会跨项目串数据，也不会覆盖用户当前展开状态。
10. 1440×900、1280×800、1024×680 以及窄屏下无文字、面板和按钮重叠；键盘焦点和减少动态效果符合系统设计标准。
11. 日志中心不显示 API Key、隐藏思维链或未授权正文，不直接修改源文档。
12. 返回来源对话后定位到发起消息；运行、暂停和失败任务具有对应的控制入口。
13. “清理后台任务记录”明确只清理终态后台任务记录，不删除对话执行日志或分析产物。
14. 表中每个 `UI-*` 均关联有效的 `BF-*`、`EP-*`，实现状态与源码和目标态缺口一致。

## 目标态缺口

- 全局任务索引、“全部项目/当前项目”范围选择和跨项目并发状态刷新。
- 统一的 TaskEvent/JobService 状态源和跨会话任务通知。
- 任务事件的分页、筛选和更完整的链路耗时聚合。
- 首次加载骨架屏、局部错误重试和结果预览内联错误，而不是依赖全局错误条。
- 超过最近 50 个对话后的增量加载、时间范围筛选和日志归档策略。
- 更完整的证据/缓存可视化，但不暴露内部实现术语或隐藏思维链。
