# Vinkey Ollama 中文创作模型组

- 状态：最低配置测试基线
- 日期：2026-09-07
- 适用范围：Vinkey 当前版本的本机 Ollama 文本质量测试

## 1. 目标与边界

本方案为 Vinkey 的“本地 AI 文学创作工作台”建立可复现的最低配置模型组。模型组表示一组按业务角色组织、按任务切换的模型配置，不表示多个模型同时驻留或并行推理。

最低配置基线为 Apple Silicon 16 GB 统一内存，或 Windows 16 GB 系统内存加 8 GB 独立显存；Windows 实际购买建议从 12 GB 显存起。模型与 Vinkey 在同一台机器运行，使用 Ollama 和 4-bit 量化，不包含训练、微调、图像生成或多模型并发。

当前首轮测试固定使用 16,384 tokens 上下文。Vinkey 的长文本任务会执行分块与 Map/Reduce/Synthesis，不以一次装入整部作品为前提，因此最低配置不追求模型标称的 64K、128K 或更大窗口。

## 2. 最低配置模型组

| 顺序 | 配置名称 | Ollama 模型 | 量化与下载大小 | 业务角色 |
| ---: | --- | --- | --- | --- |
| 1 | 轻量 · MiniCPM4.1 8B | `openbmb/minicpm4.1:latest` | Q4_K_M，约 5.0 GB | 文本提取、摘要、分块分析、批量后台任务和快速草稿 |
| 2 | 综合 · Qwen3 8B | `qwen3:8b` | Q4_K_M，约 5.2 GB | 基准、主笔、润色、对白、风格控制和人物设定审校 |

模型文件合计约 10.2 GB，建议至少预留 18 GB 磁盘空间，以容纳下载过程、模型更新和 Ollama 元数据。两个模型按需切换，同一时间只要求一个模型驻留。

最低配置组不再为“基准、主笔、审校”各自保存同档位模型。Qwen3 8B 通过不同任务模板承担三类职责，避免在 7B 至 9B 档位为能力高度重叠的模型增加磁盘、冷启动和路由成本。MiniCPM4.1 8B 单独存在，是为了验证端侧吞吐、长文本分块和后台批处理效率，而不是提供另一套主笔风格。

## 3. 安装与配置

macOS 或 Linux：

```bash
bash scripts/install-ollama-minimum-models.sh
```

Windows PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/install-ollama-minimum-models.ps1
```

在 Vinkey 中新增一个供两个功能共用的连接：

```text
接口类型：Ollama
Base URL：http://localhost:11434
API Key：留空
```

保存并获取模型后，使用“智能分配”或分别选择轻量高效、综合创作模型。上下文窗口位于各功能的“运行参数”中，本机 Ollama 新配置默认 16384。

智能分配将本地功能模型配置为 16K；Ollama `/api/chat` 请求显式传递 `options.num_ctx`，与该配置保持一致。该值是申请容量，不是硬件实测结果。使用命令行服务时，也可以设置默认值：

```bash
OLLAMA_CONTEXT_LENGTH=16384 ollama serve
```

发送首条请求后运行 `ollama ps`，确认 `CONTEXT` 为 `16384` 且 `PROCESSOR` 为 `100% GPU`。若发生 CPU 卸载或上下文不一致，该轮结果标记为环境异常。

## 4. 模型组交互

设置页上方显示轻量高效、综合创作的当前模型和连接 URL，下方管理连接及发现列表。用户保存本机 Ollama 连接后，可通过“智能分配”优先选用已安装的最低配置组成员，也可从下拉框选择其他连接中的模型；不会创建未发现模型的配置。

模型组只负责配置组织，不改变供应商无关的 `ModelProvider` 合同。本机回环地址连接的智能分配依据以下容量策略选型；局域网及云端服务沿用其可用模型列表，不使用客户端硬件推断服务端能力。

| 档位 | Apple Silicon 统一内存 | 独立显卡设备（内存 / 单卡显存） | 综合创作优先模型 |
| --- | --- | --- | --- |
| 最低配置 | 16 GB | 16 GB / 8 GB | `qwen3:8b` |
| 标准配置 | 32 GB | 32 GB / 16 GB | `qwen3:14b`，其次 8B |
| 推荐配置 | 64 GB | 64 GB / 24 GB | `qwen3:32b`，其次 14B、8B |

所有档位的轻量高效优先 `openbmb/minicpm4.1:latest`，其次 `qwen3:8b`；只选择服务已发现的上述 Q4 默认标签，不自动下载模型。综合模型不可用时也可复用 MiniCPM。未知标签或自定义量化留给手动配置。各档位暂统一使用 16K 请求窗口，以控制长文本任务单次推理的成本；档位并非模型标称窗口或实测性能评级。

macOS 通过系统物理内存及 Apple Silicon 标志识别统一内存；Windows 读取物理内存及显卡注册表中的 64 位专用显存值，并优先采用 `nvidia-smi`；Linux 读取物理内存以及 NVIDIA/AMD 专用显存。多卡取单卡最大值，不累加显存，不将系统内存加到独立显存中。允许约 3% 的系统保留内存误差。

低于最低要求时设置页直接建议连接局域网推理服务或商用 AI，并提供远程连接入口；硬件信息缺失时显示“硬件未确认”。这两种状态暂停本地智能分配，保留手动配置。手动分配不覆盖已有上下文设置；点击本地智能分配会将所选配置统一到 16K。

以上是单模型 Q4 的保守容量建议，标准与推荐档位仍需目标设备验证。后台负载、量化文件变化、驱动及 KV cache 均可能影响实际可运行容量；硬件探测不等于运行时上下文探测。此次没有实现内存不足后的自动降档或 Worker 自动重新分块。远程连接建议不改变原文数据的既有访问策略。

任务默认在“轻量高效”和“综合创作”两类功能分配之间选择，对话输入区仍支持手动指定模型。基准、主笔和审校是综合模型的任务模板，不对应三个独立模型。

## 5. 本机 Ollama 驻留策略

Vinkey 将 `ollama` 提供商且 Base URL 为 `localhost`、`127.0.0.0/8` 或 `::1` 的配置认定为同机 Ollama。模型设置提供设备级“切换时自动停止旧模型”开关，默认开启并保存在本机。开关开启时，切换到不同模型前 Vinkey 查询 `/api/ps`；旧模型正在运行时，向 `/api/generate` 发送 `keep_alive: 0`，语义等同于：

```bash
ollama stop <旧模型>
```

同一模型的不同上下文配置之间切换时不卸载。局域网 Ollama 和 OpenAI 兼容服务不会收到停止请求。其他会话仍在执行时不自动卸载旧模型。保存或删除连接不触发模型加载与卸载。关闭自动停止后，由 Ollama 自身的 `keep_alive` 与内存调度负责驻留；设置页的显式“停止驻留”命令始终可用。自动卸载失败会提示用户，但不阻止任务执行。

## 6. 首轮文本质量测试

首轮测试评估当前 Vinkey 的开箱行为，不创建自定义 Modelfile，不统一覆盖各模型的 temperature、top-p 或思考模式：

1. 两个模型使用相同文稿、相同指令和 16K 上下文。
2. 每个任务使用新会话，每个模型重复三次。
3. 切换模型时确认旧模型已经卸载，只保留一个驻留模型。
4. 覆盖短续写、选段润色、对白重写、指定风格改写、人物连续性检查和跨章节设定冲突检查。
5. 文本质量与性能分开记录；思考内容泄漏、过度推理、重复和截断均作为当前产品表现记录。

综合模型按中文自然度、风格遵循、人物一致性、情节推进、修改边界和重复退化评分；审校任务另行记录证据准确性、冲突识别、误报率和修改建议可执行性。轻量模型除相同质量指标外，重点记录首 token 延迟、生成速度、长文本分块吞吐和峰值内存。

## 7. 后续候选

- `qwen2.5:7b` 只作为当前版本的一次性回归基准，不进入正式最低配置组；完成迁移比较后可卸载。
- `deepseek-r1:8b` 只作为增强审校候选。只有在人物冲突、时间线和设定检查上稳定优于 Qwen3 8B，且收益足以覆盖额外加载与输出清理成本时，才升级为第三个成员。
- `glm4:9b` 因当前 Ollama 标签较旧且与综合模型重叠，不进入最低配置测试。
- `InternLM3-8B-Instruct Q4_K_M` 作为手工 GGUF 导入候选进行第二轮测试。
- `Seed-OSS-36B-Instruct` 只进入 64 GB Mac 或 32 GB 显存专业测试机，不属于最低配置。
- Yi、Baichuan 和 MiMo 暂作兼容观察，不进入首轮安装脚本。
