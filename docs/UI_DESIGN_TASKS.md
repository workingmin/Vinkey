# UI 设计：任务中心

- 状态：当前实现基线，Agent Runtime 扩展为目标态
- 日期：2026-09-15
- 适用端：Windows、macOS 桌面应用；浏览器模式仅提供有限演示能力
- 关联文档：[UI_INVENTORY.md](./UI_INVENTORY.md)、[UI_DESIGN_CHAT.md](./UI_DESIGN_CHAT.md)、[UI_DESIGN_STATES.md](./UI_DESIGN_STATES.md)、[TEMPORARY_INTERACTION_STATES.md](./TEMPORARY_INTERACTION_STATES.md)

## 目标与边界

任务中心用于查看当前工作区的可恢复后台任务，不承担普通对话消息流的展示，也不提供通用 IDE 的构建、终端或插件任务入口。

当前页面主要服务长文本分析和 Worker 任务：

- 查看运行、暂停、完成、失败和取消任务。
- 查看每个任务的步骤、执行次数、检查点和失败原因。
- 对可重试失败选择起始步骤并重新执行。
- 查看已完成任务的只读分析产物和运行指标。
- 以当前工作区为边界刷新任务列表，避免跨项目混淆。

任务中心不直接编辑源文档、不修改任务输入、不替代文件页的 Diff 提案审核。任务产生的草稿或修改提案仍回到对话/文件页处理。

## 页面入口

- 内容区顶栏的“任务”标签与“对话”“文件”互斥。
- 标题栏“查看”菜单提供“任务中心”命令；命令只切换内容页，不改变当前会话。
- 无工作区时仍可进入页面，但显示“未打开项目”空态，不请求任务列表。
- 设置页打开时任务中心不可见；任务执行期间设置页会锁定模型和连接修改。

## 布局

```text
内容区顶栏：会话/任务标题             对话 | 文件 | 任务
任务工具栏：运行 N    完成 N    失败 N                         刷新
任务列表：
  展开 任务名称 / taskId       状态       更新时间       操作
  展开后：失败原因（如有）
           步骤与检查点
           完成任务的运行指标和只读产物
```

### 工具栏

- 工具栏保持稳定高度；左侧按“运行”统计 `running + paused`，分别统计“完成”和“失败”。
- 右侧只有刷新按钮。刷新期间按钮禁用并显示旋转图标，列表保留原内容，避免跳变。
- 统计只针对当前工作区，由 `listTaskJobs()` 返回结果计算。

### 任务行

- 默认每个任务折叠，显示任务类型、短 task ID、状态、更新时间和操作区。
- 点击任务主按钮展开/收起详情；当前实现保持单个展开。
- 展开按钮使用 `aria-expanded`；任务名称和 task ID 在窄宽度下截断，不挤压状态或操作图标。
- 完成任务显示“查看结果”图标按钮；失败任务显示步骤选择器和“重跑所选步骤”图标按钮。

### 任务详情

- 失败任务优先显示错误代码、用户可读错误消息和“可重试/需重新发起”语义。
- 步骤使用中文短标签：文档分块、逐块分析、章节汇总、卷级汇总、最终综合、证据校验和分层归并。
- 每步显示状态、执行次数和检查点；状态不能只依赖颜色，应同时使用文字、图标或位置。
- 完成结果显示模型调用次数、跨任务缓存命中、任务内检查点命中、耗时、产物目录和结果正文。
- 产物正文保持只读，长内容在固定区域滚动，不把结果直接写回源文档。

## 状态语义

### 任务状态

| 稳定状态 | 用户文案 | 表现 | 当前实现 |
| --- | --- | --- | --- |
| `planned` | 等待中 | 中性文字，允许展开查看已规划步骤 | 已实现 |
| `running` | 运行中 | 强调色文字，步骤中显示当前执行项 | 已实现 |
| `paused` | 已暂停 | 警示色文字，计入运行统计 | 已实现（展示） |
| `completed` | 已完成 | 成功色文字，可查看结果 | 已实现 |
| `failed` | 失败 | 错误色文字，显示失败原因和重跑入口 | 已实现 |
| `cancelled` | 已取消 | 中性终止状态，不提供结果查看 | 已实现（展示） |

### 步骤状态

`pending`、`running`、`completed`、`failed`、`cancelled` 只描述当前步骤，不覆盖任务级失败原因。步骤状态、执行次数和检查点来自持久化 `TaskJob`，前端不根据等待时间猜测状态。

### 与消息活动轨迹的边界

- 消息活动轨迹位于对话消息内部，回答“这次请求正在做什么”。
- 任务中心回答“工作区有哪些后台任务、能否恢复、结果在哪里”。
- 两者可以引用同一个 `jobId`，但任务中心不重复渲染隐藏思维链或逐 token 输出。
- 任务完成后消息流突出最终回答，任务中心保留可恢复任务和产物索引。

## 核心流程

### 查看任务

1. 用户进入“任务”页。
2. 页面按当前工作区读取任务，并按 `updatedAt` 倒序排列。
3. 用户展开任务查看步骤、检查点和错误。
4. 用户点击刷新时保留已展开状态；任务不存在或工作区切换后清理失效详情。

### 重跑失败步骤

1. 失败任务显示失败步骤作为默认选择；下拉菜单仍列出全部步骤。
2. 用户选择步骤并点击重跑。
3. 页面使用确认对话框确认起始步骤，按钮进入禁用/进行中状态。
4. 后端接受重跑后刷新任务列表，清除该任务旧的结果预览。
5. 不可重试失败禁用选择器和重跑按钮，并显示“需重新发起”。

重跑必须由后端保证幂等和检查点有效性；前端不能通过重复点击制造多个 Worker。

### 查看结果

1. 只有完成任务显示查看结果入口。
2. 首次查看调用 `getLongTextWorkerOutput(jobId)`，结果加载期间保留任务详情。
3. 结果显示只读正文、产物目录和运行指标；读取失败使用全局错误反馈。
4. 结果已加载时再次点击只切换详情展开状态，不重复请求。

## 响应式与无障碍

- 桌面宽度任务行采用名称、状态、时间、操作四列；内容区最小宽度不足时任务行改为两列，时间隐藏，操作移到下一行。
- 任务详情和结果正文允许纵向滚动；长 task ID、错误消息、路径和结果文本自动换行。
- 所有图标按钮必须有可读 `title` 和 `aria-label`；展开按钮提供 `aria-expanded`。
- 重跑和刷新期间按钮禁用，避免重复请求；状态变化应使用状态文本而不是仅改变颜色。
- 深浅主题、键盘焦点、中文 IME 和 `prefers-reduced-motion` 按系统级验收标准复验。

## 数据与隐私边界

- 任务列表只显示当前工作区任务；任务输入哈希、源文件指纹和内部事件不直接作为 UI 主文案。
- 结果正文和产物路径可能包含用户创作内容，任务中心不写入浏览器历史或日志。
- 产物预览为只读，不允许在任务中心直接覆盖源文件。
- API Key、模型凭据和隐藏思维链不进入任务列表、步骤详情或结果指标。

## 验收标准

1. 从内容区“任务”标签和标题栏菜单均可进入任务中心，且不改变当前会话或工作区。
2. 无工作区、无任务、加载中、读取失败和结果失效均有稳定且可理解的状态表现。
3. 任务行至少显示任务类型、状态、更新时间和可用操作；状态文字与 `TaskJob.status` 一致。
4. 展开任务后能看到失败原因、步骤状态、执行次数和检查点，长文本不会造成布局溢出。
5. 失败任务默认选中最近失败步骤；不可重试失败不能触发重跑；重跑期间不可重复提交。
6. 完成任务可查看只读结果、产物目录、模型调用次数、缓存命中和耗时；读取失败不清除任务状态。
7. 任务列表只显示当前工作区数据，定时刷新不会跨项目串数据，也不会覆盖用户当前展开状态。
8. 1440×900、1280×800、1024×680 以及窄屏下无文字、面板和按钮重叠；键盘焦点和减少动态效果符合系统设计标准。
9. 任务中心不显示 API Key、隐藏思维链或未授权正文，不直接修改源文档。
10. 表中每个 `UI-*` 均关联有效的 `BF-*`、`EP-*`，实现状态与源码和目标态缺口一致。

## 目标态缺口

- 统一的 TaskEvent/JobService 状态源和跨会话任务通知。
- 任务中心内暂停、恢复、取消和“返回来源消息/文件”的入口。
- 首次加载骨架屏、局部错误重试和结果预览内联错误，而不是依赖全局错误条。
- 多任务筛选、按状态过滤、搜索和任务归档策略。
- 更完整的证据/缓存可视化，但不暴露内部实现术语或隐藏思维链。
